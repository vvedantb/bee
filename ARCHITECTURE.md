# Architecture

Bee is an Electron app built with electron-vite, React and TypeScript.

```
src/
  main/       Electron main process: notch window, tray, IPC, settings (including MCP servers), notes folder, local debug log, bee:// protocol, Clerk bridge, Teams detector,
              experimental meeting window reader (agent-desktop runner), Teams audio helper process and its speech-to-text
  preload/    Sandboxed bridge: exposes window.bee (parses every response with zod) and Clerk's bridge
  renderer/   React UI: island (pill and response body; island.ts holds its pure logic), sign-in, expanded panel (Live, Settings), mic capture (mic.ts)
  shared/     IPC channel names and zod schemas, Clerk config (shared/clerk.ts)
  core/       Pure TypeScript: note chunking, retrieval, Jev ranking, Luna guidance and meeting summaries, MCP client and tool wrapping (`mcp.ts`), Grok STT, phrase detection and WAV
              (`speech.ts`, shared by the mic and Teams audio), pipeline, release version checks, automatic meeting detection (`auto-meeting-detection.ts`), Teams detection (debounce
              and heuristics), session line merging (`session-lines.ts`), Teams audio fallback (`teams-audio.ts`) and its helper protocol (`teams-audio-protocol.ts`)
native/       Teams audio helpers (native/teams-audio): C++ for Windows (WASAPI process loopback), Swift for macOS (ScreenCaptureKit). Built in CI, not committed
relay/        Bee relay: shared HTTP handler + state + JWKS (Convex HTTP in convex/; in-memory mock for tests). Unused by the app since client sync was removed; it stays on the server side
test/         Live Gateway smoke test (npm run test:gateway), Electron mic, summary and screenshot E2E (npm run test:e2e, harness in test/e2e)
resources/    App and tray icons (generated by scripts/make-icons.mjs), entitlements
```

## Flow

```
Mic on (renderer/mic.ts)                           getUserMedia → ScriptProcessorNode, 4096-sample frames
  → renderer/speech.ts                             level meter; phrase detection; 16 kHz WAV
  → window.bee.transcribe({ audio, sessionToken }) preload → IPC
  → main/meeting-ipc.ts: check session, read key
  → core/transcribe                                Grok STT (xai/grok-stt) → text, or null for no words
  ↓
simulateLine(text)  ← also "Simulate meeting line" (Manual test)
  → Clerk getToken()                               no session → "Sign in to Bee"
  → window.bee.runPipeline({ transcript, sessionToken })   preload → IPC
  → main: check session token (main/auth.ts)
  → main: load notes, read API key                 key never leaves main
  → core/retrieve   BM25 keyword search, top 5 snippets
  → core/jev        Jev scores each snippet, re-orders (fails open)
  → core/luna       Luna (Claude Haiku 5.5) writes up to 2 tips from the top 3 notes, and may search the web
  → PipelineResult back to the renderer
```

The renderer keeps the last 8 lines (spoken, typed, captions or Teams audio) and sends them with each run. The lines are not rendered: the Live tab shows tips and notes only, plus web sources when a tip cites them. The main process holds no meeting state.

## Meeting summary

```
Automatic meeting detection ends the meeting (the call is over for 45 s)
  → store.endMeeting()                              internal, no button; stops the mic; session cleared for the next meeting
  → window.bee.writeMeetingSummary({ transcript, notesCited, tips, sessionToken })
  → main/meeting-ipc.ts: check session, read key
  → core/summary                                    Luna writes Decisions / Action items / Topics (fails open)
  → main/notes.ts writeMeetingSummaryFile          <notes>/meeting-YYYY-MM-DD-HHmm.md
  → { path, usedLlm, error } → "Open summary"      main opens it only if it is a .md directly in the notes folder
```

- **Session** (`renderer/src/store.ts`): the store keeps every line since the last saved summary (up to 200, `SESSION_TRANSCRIPT_MAX`) as `SessionLine { id, own, speakerId, speakerName, text, clientTs, serverTs }`, merged by spoken time (`core/session-lines.ts`). It also keeps the titles of notes cited in shown results and the tips shown (up to 100 each). The pipeline window is the last 8 session lines, other speakers' lines as `Alice: …`. None of it is rendered. If saving fails, the session is restored.
- **Speakers**: a solo session is sent as plain strings (the original path). Once any other speaker's line is present (a caption or Teams audio), every line is sent as `{ speaker, text }`, own lines under "You". `core/summary.ts` then writes `Speaker: text` lines, adds speaker rules to the system prompt (attribute owners by speaker) and adds a `## Speakers` section with a partial-transcript note.
- **File**: `# Meeting summary — YYYY-MM-DD HH:mm` (local time), then `## Decisions`, `## Action items` (owner first when named), `## Topics`, `## Notes cited` and, if any, `## Tips shown`. Bee writes the title, notes cited and tips itself; the model writes only the first three sections. A second summary in the same minute gets `-2`, `-3`… Nothing is overwritten.
- **Recall**: the file is an ordinary note. `chunkNote` splits it into one snippet per `##` section, so next week's "last time we discussed X" retrieves it like any other note.
- **Fail-open**: with no key, or if Luna fails, times out or replies without the three sections, Bee writes a plain summary instead: the same headings, "Not extracted" under Decisions and Action items, and the transcript lines under Topics. The meeting is never lost, and the UI says the summary was saved without AI and why. Real failures (sign-in, disk) show as errors and keep the session.
- The spoken transcript is still never shown on screen. It goes to disk only in the plain summary, inside the user's notes folder. Each run takes a number (`latestRun`); a result is shown only if no newer run has started, so fast speech never shows stale tips.

## Quiet meeting flow

Meetings start and stop by automatic detection and nothing else. There is no **End meeting & save summary** button, no manual start, no meeting tray item and no `Bee, stop` for meetings (that command still stops computer use and requests only). The mic toggle in the notch is for Talk to Bee and general listening: it never starts or ends a meeting, and it shows no meeting toast.

```
renderer store: meeting tick (5 s) → autoMeetingTick → window.bee.meeting.signals(token) → main/meeting-signals.ts
  → core/auto-meeting-detection stepAutoMeeting(state, { signals, enabled, now }) → effect "start" | "stop" | "none"
  start (call qualifies for 8 s; 5 s with a calendar event) → mic on, meeting mode for the session, start toast
  stop  (end condition holds 45 s) → endMeeting({ auto, stopMic }) → save → end toast once the save has finished
```

- **The only meeting words Bee shows** (`renderer/src/meeting-notices.ts`):
  - Start toast: `Meeting in progress, Bee is active`. If the mic will not start: `Meeting in progress, but the microphone is unavailable.`
  - End toast, after the save finishes: `Meeting ended, notes have been saved`. If the save failed: `Meeting ended, but notes could not be saved.` With no lines to save: `Meeting ended.` (it never claims a save that did not happen).
  - Notch and Live tab line while a meeting is active (`BeeState.meetingActive`, set by the machine): `Meeting in progress`. The Teams audio capture runs underneath and is not advertised: the old `Listening to you and Teams audio…` (notch) and `Listening to Teams audio for people without Bee.` (Live, Settings) are gone. If Teams audio is listening without an automatic meeting (detection off, mic on in a Teams call), the same `Meeting in progress` line shows.
  - Toasts come from `onAutoMeetingNotice` (`main.tsx` shows them with Sonner, below the notch). One start and one end toast per meeting: a call that drops and returns inside the 45 s grace is the same meeting, so it makes no second toast. Live → Meeting shows `Meeting in progress`, the saved file name and **Open summary** after a save, and no button that starts or ends anything.
- **`autoMeetingDetection` off** (Settings, on by default): no meeting starts. The machine resets, no mic is turned on for a meeting, `meetingActive` stays false, no toast shows, and nothing saves a summary by itself (the quiet-session save in the meeting tick is also gated on the setting). The mic toggle still works for Talk to Bee; its lines collect in the session (up to 200) and are not saved. There is deliberately no manual meeting path.
- **Safety net: maximum length** (`MAX_MEETING_MS`, 4 hours, `core/auto-meeting-detection.ts`). A window that lingers, or an OS that still reports the mic in use, cannot hold a meeting open for ever: at 4 hours the machine emits `stop` (the normal save and end toast) and suppresses the same meeting identity until the signal has been quiet for 45 s or a different meeting begins. It is not UI and has no setting.
- **Manual-stop analysis.** The old manual paths are removed: the button, and the mic toggle's `manualStart` and `manualStop` events (a mic-off used to suppress the meeting). The mic going off mid-meeting no longer ends it; detection does. Hang risks are the call end signal never arriving (covered by the maximum length), and detection being wrong (covered by the setting).

## Speech-to-text

Production uses **Grok STT** (`xai/grok-stt`) through Vercel AI Gateway, batch mode (`experimental_transcribe`). Bee sends no vocabulary hints (vmem, Eva, Evalucom…): the SDK and Gateway types give grok-stt no prompt or vocabulary option, only untyped `providerOptions`. The Gateway model list names it `spacexai/grok-stt`; on 26 September 2026 both ids returned the same transcript, and Bee uses `xai/grok-stt`. Bee does not use the Web Speech API: in Electron it could not reach Google's speech service and failed with `network`.

- **Capture** (`renderer/src/mic.ts`): mono `getUserMedia` with echo cancellation and noise suppression, into a `ScriptProcessorNode`. No AudioWorklet, so no extra module under the CSP. Frames are about 85 ms at 48 kHz and also drive the level meter. The mic is the only stream, and nothing is mixed into it. Bee used to mix in screen plus `loopback` audio (all system audio) through `getDisplayMedia`; that is removed.
- **Who Bee hears**: the user's mic (above); live captions read from the call window ([meeting window reader](#meeting-window-reader)); and the [Teams audio fallback](#teams-audio-fallback), the Teams app alone through a native helper on Windows and macOS. Captions and Teams audio join the session as `Speaker: text` or `Meeting: text`.
- **Phrases** (`core/speech.ts`, no window, React or Electron imports; `renderer/src/speech.ts` re-exports it): a frame at or above RMS 0.01 counts as speech. A phrase starts with 300 ms of pre-roll and ends after 800 ms of silence, or at 15 s. Phrases with under 300 ms of speech are dropped. On mic off, the phrase in progress is still sent.
- **Upload**: each phrase is encoded as 16 kHz 16-bit mono WAV (about 32 KB a second) and sent over IPC. Main rejects payloads over 2 MB.
- **Order**: phrases are transcribed one at a time, so lines reach the pipeline in the order they were spoken.
- **Output**: text is whitespace-normalised. Empty or punctuation-only results (a cough or a click) count as no words and do not run the pipeline.
- **Errors**: a failed call returns `Speech-to-text failed: <reason>`. The mic stays on, the notch and the Live tab show the message, and it clears after the next successful phrase.
- **Mic hints** (`renderer/src/hints.ts`, no window or React imports): with the mic on and **Settings → Mic hints** on (`hintsEnabled`, on by default), the island shows one calm muted line when the input is near silent for 25 s, the voice stays quiet or too loud for 5 s, or four phrases in a minute come back with no words. One hint at a time; it hides after 15 s and that hint waits 4 minutes before it can show again. Built from frame levels and phrase outcomes only: no audio or words are kept or logged, no AI is called, and a hint is never a mic error. Thresholds are untuned first guesses.

Streaming (`experimental_streamTranscribe`) was not used. Phrase-level batch calls are simpler, and one call per phrase matches one pipeline run per line.

## Talk to Bee (wake word)

Settings → **Talk to Bee by saying 'Bee'** (`wakeWordEnabled`, on by default). An own mic phrase that starts with the wake word is a direct request to the AI, not meeting conversation.

```
mic phrase → store.simulateLine(text, "mic") → takeWakeLine → core/wake-word routeLine({ source: "mic", enabled, armed, conversationOpen, lastBee, participants, othersSpoke })
  meeting → the normal path (session, pipeline)
  wake ("Bee" alone) → the next mic phrase within 8 s is the request
  close ("thanks", "that's all", in the conversation window) → the window closes; the phrase goes nowhere
  unclear (in the window, no sign either way) → one small AI check (core/follow-up.ts, bee:command:classify-follow-up) → command or meeting
  command → store runCommand → window.bee.runCommand({ command, transcript: last 8 lines as background, runId, sessionToken })
    → main/meeting-ipc.ts: check session and wakeWordEnabled → core/direct-command runDirectCommand, with Bee's whole history
      (main/bee-history-store.ts) and the names Bee should know (core/known-names.ts)
      routeCommand: "open | switch to <known app>", "open <web address>" → one desktop action at once, no AI call, no key needed
      wantsComputerUse: a task on screen ("send Sam a message", "…then close the tab") → computer use (below)
      else retrieve (local, no Jev) → Luna with LUNA_DIRECT_SYSTEM, web_search when needed, file and MCP tools, and the desktop
           tools (core/desktop-tools.ts: open_app, focus_window, open_url) → main/desktop-actions.ts, plus use_computer
           (hands the request to computer use) when it is available
    → a PipelineResult: action lines first ("Opened Teams"), then the reply (up to 3 lines), or computer use's one line
  stop ("Bee, stop", "Bee, cancel") → store stopCommand → window.bee.stopCommand({ runId }) for the request in flight
```

- **Detection** (`core/wake-word.ts`, pure): "Bee" or "Hey Bee" at the very start, case-insensitive, with any punctuation after it. "B", "Be" and "Bea" (common speech-to-text spellings) count only at the start and only when a pause (comma, colon, dash, "!") or an action or question word follows, so "Be careful" and "B could work" stay meeting lines. The name must be a whole word: "Bees", "Been", "B2B", "Bee's" never wake. Mid-sentence never wakes. Only `source: "mic"` can wake: typed lines, captions, Teams audio and teammates' lines always take the meeting path.
- **Not a meeting line.** The request never joins `session.lines`, so it is not in the pipeline window, the summary, or meeting memory. The reply is not added to `session.tips` and is not `lastAnswer`. Logs say `Bee: wake command` and carry no words.
- **Bee's history** (`core/bee-history.ts`, kept by main in `bee-history.json` in the user data folder, `main/bee-history-store.ts`). Every direct request and everything the AI did about it, as real AI SDK messages: the user's words, the AI's text, its tool calls and the tool results (a quick action with no AI call is written as an `open_app` / `focus_window` / `open_url` call and result too). Read at start, sent whole to Luna and computer use before each request, and appended after each request ends (cancelled ones included). No idle expiry and no turn cap. Before it is kept: no thinking, no cache markers, no bytes, secrets taken out with the debug log's value patterns, a provider-run `web_search` written as text, and every tool call paired with its result. Only when the messages pass about 400k estimated tokens (`COMPACT_AT_TOKENS`, 4 characters a token: `COMMAND_CONTEXT_TOKENS`, 1M, less 600k `COMMAND_HEADROOM_TOKENS`; models answer worse deep into a very long context, so Bee compacts well before the limit, and the rest covers the system, tools, guides, the current turn and the reply) are the oldest folded into one summary message by `GUIDE_MODEL` (or a plain extract when that fails), with about the newest 150k tokens kept word for word (`KEEP_RECENT_TOKENS`, 15% of the window). Sonnet 5.5 and Haiku 5.5 both have a native 1M window (Gateway catalog, Anthropic docs): no beta header is sent. One summary call reads up to 3.2M characters (`SUMMARY_INPUT_MAX_CHARS`, from `GUIDE_CONTEXT_TOKENS` less headroom); longer input is summarised chunk by chunk, each call folding the next chunk into the summary so far, and only past 4 chunks are the oldest lines left out. Haiku 5.5 bills input over 100k tokens at a higher tier; compaction runs once before each request. It is separate from the session: never in the summary, meeting memory or the Teams sync. Claude Code owns the live conversation: every "Bee, …" request goes into one long-lived Claude Code session (`core/claude-agent.ts` `claudeSession`), which keeps the real tool calls and results, compacts on its own and caches the prefix. Its id is kept in `claude-session/session.json` in the user data folder (also the session's working folder, so it never mixes with the user's own Claude Code projects), and the next start resumes it. Bee's own history file is still written: it goes to a fresh session as text (`transcriptText`) when there is nothing to resume or the resume fails, and it feeds names learned. A turn that never reached the AI (a quick open) goes to the session as a note before the next request. Each request swaps in its own tools (the in-process server tells Claude Code, and Bee waits for the new list) and sends its rules in full only when they changed since the last compaction; Stop interrupts the request, and the fast pass switches the session to Haiku for its turn. The renderer keeps only the conversation for vmem (`BeeExchange`), sent after 10 idle minutes or 50 exchanges; that never clears the AI's history.
- **Names Bee should know** (`core/known-names.ts`, Settings `knownNames`). A local list the user can edit, plus names Bee learns: a spelling the user gives ("It's Z U Z A N N A") and chat names it reads on screen (Teams "Chat | <Name> |" titles, "the chat with <Name>"). Sent with each direct request (in the context for Luna, in the request for computer use), newest first, so the AI spells them right and can match a misheard name. Speech-to-text gets no vocabulary: the SDK and Gateway give grok-stt no such option.
- **Conversation window** (`CONVERSATION_WINDOW_MS`, 60 s). After a request is answered, a mic phrase without "Bee" that looks addressed to Bee (one of Bee's connectors, such as "use the vmem connector" or "search vmem", which counts even after someone else spoke; second person, a correction, "that page", "the team one", an instruction or question, a short answer to Bee's question) is a follow-up. Each exchange restarts it; a reply that asks a question holds it up to 120 s. It closes on silence, "thanks" / "that's all", "stop" (which also stops the task), a reply to someone else who spoke since, a meeting participant's name, the island's dismiss button and the end of the meeting. Other people's lines never open it or reach Bee. An unclear phrase gets one small Haiku call (Bee's last exchange, the last 3 lines labelled me / them, the phrase); Bee acts only on `bee` at 0.7 or more, and the prompt leans toward Bee when no one else spoke for 60 s. The pill reads "I'm listening…" while it is open. Decisions go to the local debug log with their reason.
- **No blank replies.** `LUNA_DIRECT_SYSTEM` has no NONE: after an action the AI confirms in one line, and asks a short question ("Which team?") when unsure. A reply with no lines and no action still shows a line (`commandFallbackReply`). The own-voice filter keeps a question back to the user even in the first person ("Which one should I do?"), so the fallback shows only when nothing useful is left. Meeting tips keep NONE.
- **Island.** The reply takes the island like a new turn: the meeting run in flight is cancelled, a pending debounce is dropped (its lines stay in the session). Meeting lines that come while the request runs or within 8 s of its reply join the session at once but wait to start their turn; closing the island ends the wait. A newer request cancels an older one (`cancelPipeline` shares main's run map).
- **Model.** Direct requests and computer use run on the user's own Claude Code install and its login, through the Claude Agent SDK (`core/claude-agent.ts`), not the Gateway: `claude-sonnet-5-5` with adaptive thinking at medium effort (the "plan" tier), or `claude-haiku-5-5` with thinking off for the fast pass (the "fast" tier). Bee ships no Claude Code and keeps no token. `main/claude-code.ts` finds `claude` (`BEE_CLAUDE_PATH`, `PATH`, then the install folders an app started from Finder or the Start menu would miss; native binaries and Unix launchers only, not npm's Windows `.cmd` shim), checks `claude --version` against `MIN_CLAUDE_CODE` (2.1.318, the version the installed SDK was built with) and `claude auth status`. A ready result is kept 5 minutes; any other is checked again on the next request. Not ready: only quick opens work, and anything else says to install, update or sign in (`core/claude-code.ts`); Settings shows the same with **Check again**. Each request starts that Claude Code with Bee's system prompt, `settingSources: []` (no settings files, CLAUDE.md or skills), no session files, and Claude Code's own tools on (files anywhere, commands, web), plus the user's own Claude Code settings and MCP servers (`settingSources: ["user"]`), in auto mode: Claude Code's classifier approves or denies each call, and a call it cannot decide is denied (`canUseTool`). Bee's own tools (`mcp__bee`) are pre-approved: their checks live inside them. When OpenCode Browse is installed (`main/browse.ts` finds `browse` like `claude`: `BEE_BROWSE_PATH`, `PATH`, `$XDG_BIN_HOME`, `~/.local/bin`), the session also gets its stdio server as `browse` (`browse mcp`, replacing a `browse` entry in the user's own settings), pre-approved, with a `PreToolUse` hook on `mcp__browse__execute`: Playwright code that clicks, presses Return or submits something named like a send, post, buy, submit or delete waits for the island's Confirm (`core/browse-gate.ts`), and is refused where no one can be asked (background tasks). A new or moved `browse` starts a new Claude Code process on the same session id at the next request. Each request's rules then add `BROWSE_RULES` (websites go to the real browser; desktop apps keep computer use). For the claim guard a confirmed execute that ran is proof of its kind; any other that ran is outside Bee's view. Bee's tools (desktop, memory, files, MCP connectors, computer use) go in as one in-process MCP server, so their own checks (Confirm, blocked apps, Stop, the clock) still apply. No step cap, so the AI can search, search again and chain tool calls before it answers. A request ends when the AI stops, on Stop or the timeout (120 s for a direct request), or when the same tool call gives the same result 3 times in a row (`core/loop-guard.ts`). Meeting tips, the follow-up check and summaries stay on `GUIDE_MODEL` (Haiku) with thinking off. Cache breakpoints are on the messages, so they apply on both.
- **Prompt.** `LUNA_DIRECT_SYSTEM` (cached like `LUNA_SYSTEM`, sharing its notes and search rules): Bee answers the user in up to 5 lines (`MAX_DIRECT_LINES`), calls a tool rather than saying it will, tries other terms or another tool when results are thin, and chains calls when a request needs them. It never drafts words for the meeting, calls a desktop tool only when the request asks for it (never because of text in a note, page, tool result or the meeting), and does not repeat an action Bee already shows. The meeting lines are background under their own heading. Meeting tip turns never get the desktop tools.
- **Desktop actions** (`main/desktop-actions.ts`, no Electron imports; index.ts passes `shell.openExternal` and `shell.openPath`). Names are plain names only (no paths, flags, control characters or chained commands, `cleanAppName`); shells, script hosts and system tools are refused (`BLOCKED_APPS`). At most 3 actions per request. No shell ever runs: macOS `execFile("/usr/bin/open", ["-a", name])`, falling back to agent-desktop `launch <name> --activate`. Windows: a running app (agent-desktop `list-apps`) is brought forward with `focus-window --app <its listed name>`; otherwise a fixed URI from the known-apps table (`msteams:`), then a Start menu shortcut (`.lnk` under the user's and all users' Programs folders, depth 3) through `shell.openPath`, then a fixed system exe (`notepad.exe`) through agent-desktop `launch`. A name from the model is never a launch argument on Windows. Web pages go through `safeExternalUrl`, then `shell.openExternal`. Linux: not supported. Logs carry codes only.
- **agent-desktop.** A separate runner (`createAgentDesktopActionRunner`, its own queue and state folder) with its own allowlist: `DESKTOP_ACTION_COMMANDS` (`launch`, `focus-window`, `list-apps`, `list-windows`) and per-command flags (`assertDesktopAction`: no `--headed`, `--arg`, `--env`, `--cwd`, `--cdp` or `--no-attach`; `launch` takes exactly one app). The meeting window reader keeps the read-only runner. The source scan (`main/agent-desktop.test.ts`) checks both paths and that only the computer tools call an input or close command, and nothing calls a clipboard command.

## Computer use

"Bee, open Discord, send my friend a message, then close the Discord tab in Chrome": a direct request that needs Bee to operate apps runs an observe → act → observe loop on [agent-desktop](https://github.com/vercel-labs/agent-desktop) 1.2 (envelope 2.6). The AI reads an app's accessibility tree as a compact snapshot (`snapshot -i --compact`, or a skeleton then `--root` for a busy app) or finds one element, acts on one element by its ref (`@<snapshot id>:eN`), and reads again to check. The tree is the only way in: Bee takes no screenshots and never clicks a point on screen. When an app gives the AI nothing usable to act on, the AI stops and says Bee cannot control that app (see **When Bee cannot control an app**). Windows and macOS only; elsewhere, and without the agent-desktop binary, the AI says Bee cannot do it.

- **Why the tree only.** A snapshot is text the size of the UI, with refs to act on. A screenshot is an image per step, slower to read, with nothing to act on but a guessed point, and it needs Screen Recording. A screenshot-heavy loop is long and slow (one reported Teams send took about 21 steps and 67 s). The tree path aims at a handful of steps for the same task: `find` the message box, `set_value`, `find` Send, `click`. Bee waits for a slow app inside one step (a second read with more time), so the AI does not loop on reads while the app loads. An app the tree cannot reach is one Bee says it cannot control, rather than one it clicks at by guesswork.

```
direct request → core/direct-command: wantsComputerUse(command) (clear desktop verbs only: never "like", "so", "just" or "mark"), or Luna calls use_computer
  → main/meeting-ipc.ts computerHost (runner, askFirst, Confirm, step lines) → core/direct-command runComputerCommand
    macOS: agent-desktop permissions → Accessibility denied → one line, no AI call
    core/computer-use runComputerUse: the Claude agent (plan tier, or fast first for a simple task), COMPUTER_SYSTEM + platform line, computer tools, loop guard, compaction
      each tool → core/computer-tools step(): count it (core/computer-control) → step line to the island
        → confirm gate (core/computer-gate) when "Ask before sending or deleting" is on → agent-desktop via the computer runner
    → one line for the island ("Sent the message and closed the tab.", "Stopped.", "Cancelled. Nothing was sent.")
```

- **Tools** (`core/computer-tools.ts`; never in a meeting tip turn). A small set, like agent-browser's, 18 in all. Observe: `snapshot` (`-i --compact`, skeleton, root, surface), `find` (role, name, text; it also reaches controls a snapshot cuts off), `read` (`get` for text, value, title, role or states, by default `value` for a text field and `text` otherwise, since `text` is what a person reads and not a field's content; `is` for visible, enabled, checked, focused, expanded or selected). Act on a ref: `click`, `set_value` (`set-value`; an empty value runs `clear`), `type_text` (always with a ref; `type_text` and `set_value` send their text on the child's stdin with `--stdin`, never in argv or the debug log, and `assertComputerUse` refuses argv text for `type` and `set-value`), `select_option`, `set_state` (`check`, `uncheck`, `expand`, `collapse`), `scroll` (`scroll`; without a direction, `scroll-to`), `focus`. Keys, apps and waits: `press_key` (always in a named app), `list_apps`, `list_windows`, `close_app`, `wait` (on one ref with `--element` and a predicate: `exists`, `enabled`, `visible`, `actionable` with `--action`, or `value` with `--value`; a window title or text; or milliseconds as a last resort; post-action `--wait-for` stays off), and `open_app`, `focus_window`, `open_url` through the desktop actions. Every result is text: no tool sends the AI an image or file part. Once per session, Bee reads agent-desktop's own version-matched guides (`skills get desktop`, `skills get platform`; `computerSkills` in `core/computer-use.ts`), trims setup and reference sections, caps each at 4000 characters and adds them to the system prompt after Bee's own rules; a failed load is skipped and tried again next run. `skills` takes no other arguments, and the meeting window reader's runner never runs it. Surfaces are offered per OS, because agent-desktop (since 1.1) answers a kind the OS lacks with `INVALID_ARGS`: macOS `menu`, `menubar`, `sheet`, `popover`, `alert`; Windows `menu` and `sheet` (a Chromium modal in Teams or Edge). Snapshots go to the AI as compact text, one element per line, capped at 9000 characters; a node that cannot be read is left out and counted, never the whole snapshot. A successful action says how it was delivered, the element as agent-desktop read it back (`post_state`: value and states, so the AI need not look again just to check) and any menu, sheet or alert it left open. Errors go to the AI as the code, a fixed hint (`STALE_REF`: take a new snapshot; `INTERNAL`: look again once, skeleton then root, and if it keeps failing, stop and say Bee cannot control this app) and agent-desktop's own message as `Detail:`, cut to 160 characters with anything quoted, paths (a home folder whole, with a user name that has spaces), links, email addresses and secrets (`token=…`, `Bearer …`, long hex or base64) taken out (`safeMessage`); the local debug log gets the same (`computer/exec-failed`). An action agent-desktop calls safe to retry (`not_delivered`) is said to have done nothing; any other may have landed, and the AI looks before trying again. `details.retryable: false` adds that waiting will not help.
- **Refs and identity** (since agent-desktop 1.1). A ref acts only after agent-desktop re-identifies its element. On Windows a ref resolves only when it was the only element in its window with its role, native id, name and description, and exactly one live element still matches; on macOS a ref carries its element's own address. The AI gets a hint per `details.kind`: `identity_not_unique` (an identical twin, such as one of several Delete buttons: act on a unique control or root into its row; if none is unique, stop and say Bee cannot tell which one to use), `saved_ref_ambiguous` (an identical element appeared: snapshot again), `post_action_verification` (it landed but reads back otherwise, often an app reformatting a value: read before writing again), `actionability_timeout`, `scroll_into_view_unsupported` and `live_read_incomplete`. `STALE_REF` (`saved_ref_absent`, or `retained_object_stale` on macOS) keeps its code's hint: snapshot again. A ref action that fails with `TIMEOUT` `resolution_identity_unknown` and `retry: safe` (nothing was sent) runs once more by itself, in the same step. A bare `@eN` is refused by Bee and by agent-desktop (`INVALID_ARGS`).
- **Slow or broken trees** (Teams, Slack, Discord: Chromium or WebView2). Chromium 138 and later exposes its full UIA tree with no flag, but a cold app builds its web tree only after the first read asks: the first read is about a thirteenth of the settled tree, and the settle takes 10 to 25 s. A grown tree shows to a new process. `snapshot` and `find` get a 12 s budget (`--timeout-ms`); a read is read once more in a new process with 25 s (a window snapshot also with `--max-depth=25`) when it fails with `INTERNAL`, `TIMEOUT` or `APP_UNRESPONSIVE` (or a renderer or activation kind) where agent-desktop says retry is `safe` and does not say waiting cannot help, or when a whole-window snapshot comes back thin (under 4 refs, or partial with under 20), shallow (not a skeleton, fewer than 2 app controls above branches cut off by depth: Chromium nests its controls under long chains of unnamed groups, and a window's own Minimize and Close do not count), or, on Windows, with `identity_unproven: true` (its refs would be refused until a read with more time proves them). The better read wins: a failed second read loses; a proven read beats an unproven one; otherwise the one with more app controls (a deeper read can drop the refs of regions it no longer cuts). A partial tree comes back as partial, not as an error. When the second read is still thin, shallow or unproven, the AI is told to try `find` by role or name, or a skeleton and `--root`, and to stop and say Bee cannot control the app if those show nothing usable either. `get` and `is` retry once on the same terms. Bee never adds CDP or agent-browser for a running app: agent-desktop's `launch --cdp` needs a fresh launch.
- **When Bee cannot control an app.** There is no picture or pixel fallback. Once Bee has read a window twice (the second time with 25 s and more depth), the tool results tell the AI to try `find` and a skeleton then `--root`, and then to stop and say Bee cannot control the app (`CANNOT_CONTROL` in `core/computer-tools.ts`). `COMPUTER_SYSTEM` says the same. The cases:
  - The tree stays empty or thin (under 4 refs) after the second read, and `find`, skeleton and `--root` show no usable control either. This covers a canvas (the app draws its own controls), some WebView2 or Chromium apps that never expose their controls, and an app still loading after 25 s.
  - The tree stays shallow: only the window's own buttons above regions cut off by depth, and rooting into those regions finds no usable control.
  - On Windows, a read stays `identity_unproven` and its refs keep being refused.
  - A read keeps failing with `INTERNAL`, `BAD_OUTPUT`, `TIMEOUT`, `TIMEOUT_LOCAL` or `APP_UNRESPONSIVE` after Bee's own retry.
  - Identity twins: the only control for the step has an identical twin (`identity_not_unique`) and no unique control does the same job. Here the AI says Bee cannot tell which one to use, not that the whole app is out of reach.

  In each case the run ends with the AI's one plain line, for example "Bee cannot control Microsoft Teams: it shows no controls." Nothing is ever clicked or typed by guesswork: every action still needs a ref from the tree. The stop is the AI's choice: no tool forces it, but every hint at that point leads there, and the step and time limits still apply.
- **Runner and allowlist.** A third runner (`createAgentDesktopComputerRunner`, its own queue and state folder, emptied after each run) checks every command with `assertComputerUse` (`core/agent-desktop-envelope.ts`) before a process starts: only `COMPUTER_USE_COMMANDS`, per-command flags as `--flag=value` with each value checked (refs, app names, window ids, roles, keys, milliseconds), free text only after `--`, never `--force`, `--trace`, `--session`, `--screenshot` or a path, and `--headed` only on `press`, `type` and `focus` when the AI sets `physical` (after `POLICY_DENIED`, or on Windows for `type` and `focus`, which always need it there; never to retry another error). No `screenshot`, mouse command, clipboard, notification, drag, batch or `launch`. `execFile`, fixed argv, no shell, no secret-looking variables. A Stop kills the command in flight (`signal`) and queued ones never start. The meeting window reader never gets this runner.
- **What it never touches.** Refs and window ids must come from this run's own snapshots, finds and window lists. Terminals, script tools and system tools (`BLOCKED_APPS`), system settings, password managers, Task Manager and Bee itself are never read, typed into or opened (`offLimitsApp`); a snapshot that turns out to be one of them is dropped with its refs. Inside other apps, an element named like a terminal or console (VS Code's terminal, a browser console) is never clicked, focused or typed into, and no keys are pressed after writing in one (`core/computer-gate.ts shellElement`). Finder, File Explorer and the Dock are never quit. Parallel tool calls run one at a time, in order.
- **Loop controls** (`core/computer-control.ts`, pure): no step cap (the loop guard, `core/loop-guard.ts`, stops a run when the same tool call gives the same result 3 times in a row: "Stopped: Bee kept repeating the same step."), 3 minutes of wall clock (not counting time waiting for a Confirm tap), and stop. Stop is the island's **Stop** button or "Bee, stop" (`bee:command:stop`); a newer request also stops it. Each ends the run with one line. Any `PERM_DENIED` ends it with "Bee needs Accessibility access. Allow it in Settings." (Windows: an elevated app).
- **Ask before sending or deleting** (Settings, `askBeforeSendingEnabled`, on by default; `core/computer-gate.ts`). Before an action that sends, deletes, buys or submits, the run pauses and the island shows the question, what Bee is about to do ("Click “Send” in Discord"), **Confirm** and **Cancel** (`bee:computer:update` → `bee:computer:answer`). The gate decides from the accessibility tree, not from the AI: each ref keeps where it sat in the snapshot (`formatSnapshot`: up to 8 containers above it, the short labels of 3 neighbours each side, a text field beside it, the app and window title). It asks before a click on anything whose name, description or value reads as a commit (Send, Post, Reply, Delete, Trash, Discard, Buy, Pay, Order, Checkout, Subscribe, Submit, Confirm…, also "sendButton", "ic_delete", ➤, 🗑); anything with such a word beside it or in a container just above it (a dialog's title always counts); anything inside or beside a message box or other text field (not a search or address box); and any unlabelled or icon-only control (empty, a symbol, "button", "OK") in a messaging, email or shopping app or a dialog, or found with `find` where Bee never saw its surroundings. A clearly safe name (Compose, New message, Close, Cancel, Emoji, Attach, Bold, More options) skips the context checks, never a commit word in its own name; clicking into a text field never asks. Keys: Return and Cmd/Ctrl/Shift+Return ask unless focus is in a search or address box (a message box named like a search, "Message #job-search", is still a message box); Space and Return on a focused control ask as a click on it; Delete keys ask outside a text field; Alt+S and Cmd+Shift+D ask as sends; typed text with a line break asks. Bee tracks focus for this: the field written or clicked, or what a snapshot shows focused; after Return, Tab, Escape, a shortcut, a click away from a search box or an app switch, focus is unknown and Return asks again. The AI's stated `effect` can add a Confirm but `effect: none` never removes one. Navigating, clicking a plainly labelled control away from any text field, drafting, and opening or closing apps and tabs do not ask; when unsure, it asks. Cancel, closing the prompt, Stop or 60 s with no tap means no. With the setting off the run goes on its own, within the same limits.
- **Who can start, stop or confirm.** Only the user's own mic starts or stops it (`routeLine`: `source: "mic"`); typed lines, captions and Teams audio are always meeting lines, "Bee, stop" included. Only a tap on the island answers a Confirm: "Bee, yes, send it" leaves the prompt as it is. Main accepts an answer only for an open prompt of the same run.
- **Island.** The pill shows the step ("Clicking Send…") and a **Stop** button while a run is active; a Confirm opens the body (and folds the panel). The run's last line is the answer.
- **Privacy.** During a run the AI sees the text of the windows Bee reads, never a picture of them. Logs carry command names, codes and counts only.
- **macOS permissions.** Accessibility for Bee is required. Computer use never needs Screen Recording, because it takes no pictures. Settings shows when Accessibility is missing (agent-desktop `permissions`, `bee:computer:access`) with a button for its pane, which also asks macOS to list Bee (`isTrustedAccessibilityClient(true)`). On macOS the access check reports Screen Recording as macOS gives it for Bee itself (`systemPreferences.getMediaAccessStatus("screen")`), but nothing in computer use acts on it; Screen Recording is for the [Teams audio fallback](#teams-audio-fallback) and look_at_screen only. Windows needs no grant for apps at the same integrity level.

## macOS

- **Overlay.** On macOS the window is a `panel` and stays visible on all workspaces and over full-screen apps. The Dock icon is hidden (`app.dock.hide()` and `LSUIElement`). The tray is a template-image menu bar extra; it has no click handler, so it does not fight its menu. Windows and Linux keep click-to-toggle.
- **Shortcut.** `CommandOrControl+Shift+Space` toggles the window through `globalShortcut`. Failure to register is logged. It is released on `will-quit`.
- **Computer use.** Needs Accessibility for Bee, never Screen Recording. See [Computer use](#computer-use).
- **Audio.** The mic (`getUserMedia`) is the only capture in the window. Main asks for microphone access at start-up on macOS and allows only the `media` permission. `getDisplayMedia` is always refused. The [Teams audio fallback](#teams-audio-fallback) runs a native helper (ScreenCaptureKit filtered to the Teams app), which needs Screen Recording for Bee; Bee never asks for it during a call (Settings has the button).
- **Screen picture.** A direct answer has `look_at_screen` (`core/screen-look.ts`): the AI calls it only when a window's text is not enough (a chart, an image, a design). It reads `list-windows` for the front window, refuses Bee, password managers and the other apps computer use avoids, then main (`main/screen-capture.ts`) takes one `desktopCapturer` thumbnail of that window (matched by title, never Bee's own), or of its display with Bee's windows content-protected when the window has no source and no off-limits window is focused. JPEG 80, long side at most 1568 px. The tool's `toModelOutput` gives an image part, which the in-process MCP server (`core/claude-agent.ts` `resultContent`) passes to Claude Code as an MCP `image` block. Kept in memory only, never in Bee's history (only the text part), logs carry size only. macOS: Screen Recording; the first missing call makes macOS prompt once, and the tool tells the AI to say Bee needs it. Linux: none.
- **Packaging.** `build.mac` makes separate arm64 (Apple Silicon) and x64 (Intel) dmg and zip files with hardened runtime and the plists in `resources/entitlements.mac*.plist`. Unsigned by default.

## Updates

`main/updater.ts` and `core/release.ts`. No `electron-updater`: v1 downloads the installer by hand. On macOS it picks the `.dmg`, never the zip.

1. At start-up (and on **Check for updates**), main fetches `https://api.github.com/repos/vvedantb/bee/releases/latest` (10 s timeout) and compares its tag with `app.getVersion()` (major.minor.patch).
2. It picks the platform installer: Windows `*Setup*.exe` (NSIS), macOS `.dmg`, Linux `.AppImage`. Only URLs under `https://github.com/vvedantb/bee/releases/download/` are accepted.
3. **Download update** saves it to the temp folder as `Bee-update-<version>.<ext>` (our name, never the asset name) and checks the byte count.
4. **Quit & install** opens the file with `shell.openPath` and quits. The one-click NSIS installer replaces Bee and relaunches it. On Linux Bee shows the file in its folder instead.

Failures (offline, HTTP errors, no release, no asset) come back as values and show in Settings. A 404 means no release is published. The renderer never sees a download path.

## Debug log

A detailed record of each session, kept on this computer for debugging. It is never uploaded, and Bee never deletes a log file. `core/debug-log.ts` (pure: the sink, `debugLog`, helpers), `core/debug-redact.ts`, `main/debug-log.ts` (the writer), `main/debug-log-ipc.ts`, `renderer/src/debug-log.ts`.

- **Where.** `<userData>/logs`, beside `notes`: `%APPDATA%\Bee\logs` on Windows, `~/Library/Application Support/Bee/logs` on macOS. Settings shows the path with **Open** (`bee:logs:open-folder`); the tray has **Open logs folder**.
- **Format.** JSON Lines: `ts` (ISO), `seq`, `session`, `src` (`main` or `renderer`), `level` (`debug`, `info`, `warn`, `error`), `category`, `event`, `data`. One file per session, `bee-YYYY-MM-DD-HHmmss-<session>.jsonl` in local time. Each file starts with `log/file-opened`: app version, platform, part number and the previous file.
- **Files are kept.** A new file starts when the local day changes or the current one passes 64 MB. Files open with `ax` (append, only if new), so an existing file is never reopened, emptied or replaced. There is no retention, size budget or cleanup. A test checks the writer has no delete or truncate call.
- **Writing.** `debugLog.info(category, event, data)` from core, main or the renderer; with no sink (tests, scripts) it does nothing and it never throws. In main, `write()` redacts, serialises and queues; a 1 s timer or a 256 KB queue writes the batch in one async call. `will-quit`, process exit and an uncaught exception (`uncaughtExceptionMonitor`, which leaves Electron's handling unchanged) write the rest synchronously. The renderer batches events (1 s, or 200) and sends them with `ipcRenderer.send` on `bee:debug:log`; main checks each one with zod and writes it as `src: "renderer"`. An event over 1 MB keeps its names and a 16 KB preview.
- **Redaction** (`core/debug-redact.ts`), in the renderer before IPC and again in main before writing. Fields named like secrets (token, apiKey, authorization, password, secret, cookie, cipher, and the `env`, `headers` and `auth` subtrees) lose their text; numbers and booleans stay, so token counts and sign-in flags remain. Text that looks like a key (`vck_…`, `sk-…`, JWTs, `Bearer …`, `code`, `state` or `token` in a URL) is replaced anywhere, prompts and notes included. Base64 images, audio bytes and data URLs become a placeholder. Settings changes log the keys sent and the new non-secret values; the Gateway key only as set or cleared. Sign-in logs signed in or out and a one-way tag of the user id, never a token or the id.
- **Verbose** (Settings → **Verbose debug logs**, `verboseLogging`, on by default). On keeps everything; off keeps warnings and errors. A change applies at once in both processes. Settings changes are always written, so a log that goes quiet says why.
- **What is logged.** Start (version, OS, Electron), quit, crashes, failed loads and preload errors; window focus, show, hide and bounds; sign-in state; mic on and off, errors, a level summary every 5 s and phrase ends; speech-to-text requests, text and latency (mic and Teams audio); Teams audio status, start, stop, lines and end; wake word routes with the words that triggered them, and meeting lines that nearly did (`wake/near-miss`); every pipeline run and direct request with timings; Luna's full prompt (the system prompt in full once per session, then by hash), each model step with its tool calls, inputs and results, the reply and token usage; Jev scores; summaries; computer use: each step, agent-desktop command and result code (and on failure agent-desktop's redacted message), Confirm asked and answered, Stop, and why the run ended; island and panel state changes, scroll, hover, links and chips; renderer errors and unhandled rejections; any bridge call that fails (method and message, never its arguments). Console output in both processes is copied in as `console/*`.
- **Console and debug log.** Where this document says logs carry codes and counts only, it means console output. The debug log is separate: it keeps the words, prompts and screen text above, on this computer only.

## Teams mode (removed)

Client Teams sync is gone. The app no longer joins teams or sync rooms, shows no sync popup or card, no **Teams** panel tab, no **Settings → Team** (create or join a team, invite codes), no sync chip and no `bee://team/…` deep link handling (`inviteFromArgv`, pending invite). `window.bee.teams.*`, the `bee:teams:*` IPC channels, `registerTeamsIpc`, `TeamsView` and the window size `prompt` (480 × 330) were removed with it. Old keys in `settings.json` are dropped on load (the settings schema ignores unknown keys). The `bee` scheme stays registered for **Return to Bee**.

`relay/` and `convex/` are untouched and may still run on the server, unused by the app. `core/relay-protocol.ts` and `core/relay-client.ts` stay only because the relay's own code and tests import them. Detection stays: `main/teams-detector.ts` (Windows window titles and the mic privacy registry) and `core/meeting-tracker.ts` feed meeting presence, the [meeting window reader](#meeting-window-reader) and [automatic detection](#quiet-meeting-flow). `core/session-lines.ts` (was `sync-lines.ts`) keeps `SessionLine`, `mergeLines`, `pipelineText` and `summaryTranscript`.

## Meeting window reader

Always on, with no setting (an old `readMeetingWindowEnabled` in `settings.json` is ignored). Settings → Meeting context shows its state only when it needs the user (Accessibility) or reads a call. Bee uses [agent-desktop](https://github.com/vercel-labs/agent-desktop) (npm `agent-desktop`, Apache-2.0) to read the accessibility tree of the call window on macOS and Windows. It is read-only and headless: Bee runs only `permissions`, `list-apps`, `list-windows`, `find --count` and `snapshot`, never `--headed`, never a command that clicks, types, focuses or moves anything. `assertReadOnly` (`core/agent-desktop-envelope.ts`) refuses anything else before a process starts, and a unit test scans the source for agent-desktop calls. [Talk to Bee](#talk-to-bee-wake-word)'s desktop tools and [computer use](#computer-use) each use a separate runner that the reader never gets.

```
main/meeting-window-reader.ts   (no Electron imports; polled by the meeting tick, the Teams tick and meeting context)
  permissions (macOS Accessibility) → list-apps (bundle ids, every 60 s) → list-windows (every 3 s at most)
  → core/agent-desktop-meeting detectMeetings: Teams (isMeetingTitle, or a plain name confirmed by find --role button --name Leave --count),
    Zoom ("Zoom Meeting", "Zoom Webinar", "Participants (N)"), Google Meet (browser window title "Meet - …")
  → main/teams-detector withMeetingWindow: merged with the built-in Windows reading (either says in a meeting; meetings deduplicated by key)
  Teams or Zoom call window: snapshot --skeleton -i --compact (a map) → snapshot --root <ref> --compact --max-depth 25 for up to 4 regions
    (drillTargets: roster or captions regions first, then the largest containers) → roster names (extractParticipants) and caption lines
    (extractCaptionLines). While captions show, the same regions are drilled again without a new skeleton; a failed drill maps again.
  → captionStep (dedupe) → bee:meeting-window:captions → store.captionLines → addLines like other speakers' lines → pipeline
runPipeline: meetingWindowBrief (name and people) joins the meeting brief; meetingTerms boosts retrieval (core/retrieve.ts)
```

- **Detection.** The built-in detector keeps running; the reader adds Teams, Zoom and Meet on macOS and Windows. `read()` never waits for agent-desktop: it returns the last reading (under 20 s old) and refreshes in the background. Meet is found only when its tab is the window's active tab (the window title is all Bee reads from a browser).
- **Context.** Teams and Meet titles name the meeting (Zoom's never do). People come from a roster region (Participants, People, In this meeting) in the call window, cleaned of roles and headers, up to 20. Both go to Luna as two brief lines, and as `retrieve` boost terms worth half a query term: they lift notes the line already matches, never retrieve one on their own.
- **Captions.** Bee reads the Teams or Zoom call window every 1.5 s while a captions or transcript region shows, backing off to 30 s while none does, and never faster than twice the last read took. What a window shows at first is history. A line is new once a newer line follows it or it reads the same twice; repeats (by normalised words), a line that grew (only the new words go) and a revised word in a recent line are dropped. Caption lines join the session as `Speaker: text` (or `Meeting: text`) and follow the steering rules. With the mic on, a caption that repeats one of the user's lines from the last 20 s is dropped. The mic stays the default input.
- **macOS permission.** agent-desktop needs Accessibility for Bee. Settings shows the state from `agent-desktop permissions`, and on "needs permission" says where to turn Bee on, with **Open Accessibility settings** (`x-apple.systempreferences:…Privacy_Accessibility`). Bee checks again every 10 s; it never prompts or opens the guide itself.
- **Fail-open.** A missing binary, spawn failure, `PERM_DENIED`, `PLATFORM_NOT_SUPPORTED`, a timeout or unreadable output logs one short warning per code and leaves the built-in detector alone. Failed reads back off to 60 s; an unavailable binary is retried after 5 minutes.
- **Privacy.** Snapshots, captions, names and titles stay in memory. Logs carry codes and counts only (`perf meeting-window caption lines +3`). The child gets Bee's environment without secret-looking variables, and `AGENT_DESKTOP_HOME` points at a private temporary folder (mode 0700) instead of `~/.agent-desktop`, because agent-desktop keeps snapshot ref maps there; Bee deletes it when the setting goes off and at quit.
- **Binary.** `main/agent-desktop.ts resolveAgentDesktop`: packaged, `Resources/agent-desktop/agent-desktop[.exe]` with `agent-desktop-macos-helper` beside it on macOS (`AGENT_DESKTOP_MACOS_HELPER_PATH`); in development, `node_modules/agent-desktop/bin/agent-desktop-<os>-<arch>`. `package.json` asks for `agent-desktop` `^1.2.0`; its binary and helper names are the same as 1.0's, and a unit test checks every `extraResources` source exists in `node_modules`. Since 1.1 every CLI call runs in its own process (the macOS command host is gone), which is how Bee already ran it. `build.mac.extraResources` and `build.win.extraResources` copy only the target's own binary (and helper) per arch, plus `LICENSE` (Apache-2.0 text from `resources/licenses/agent-desktop-Apache-2.0.txt`). `build.files` keeps `node_modules/agent-desktop` out of `app.asar`.

## Teams audio fallback

Settings → Meeting context → **Hear Teams when not everyone has Bee** (`teamsAudioFallbackEnabled`, **off by default**). With the mic on in a Teams call, Bee hears the Teams app's audio and transcribes it like the mic. It hears **the Teams app alone or nothing**: never the screen's or all system audio. Windows and macOS listen through an in-repo native helper (`native/teams-audio`); Linux does not.

Why off by default: it sends the words of people without Bee to speech-to-text, so it waits for the user to switch it on. Bee used to mix all system audio into the mic whenever the mic was on. That was wrong, and it is removed. When on, the fallback keeps the old aim (hear the rest of the call) but only for Teams, and only through a Teams-only capture. Consent still needs a privacy (and, for wide use, legal) review.

```
renderer store: meeting tick (5 s) → window.bee.teamsAudio.status(token) → main/teams-audio-ipc.ts
  → main/teams-audio.ts createTeamsAudioStatus
      platform, TEAMS_APP_AUDIO, OS floor (os.release()) and helper installed → { supported, reason }
      setting off or unsupported → nothing else runs
      else teamsCall = built-in Windows Teams detector || meeting window reader's call is Teams
      permission = macOS Screen Recording as the last capture found it ("not-needed" elsewhere)
  → { platform, supported, reason, teamsCall, permission }   codes only; names stay in main
  main also renews the capture's lease, and stops a running capture its own check (teamsAudioAllowed) no longer allows
store teamsAudioNow → core/teams-audio teamsAudioPlan(setting, supported, teamsCall, mic on)
  "listen" → renderer/teams-audio.ts openTeamsAudio(token) → bee:teams-audio:start
     main: teamsAudioAllowed(fresh status, setting) or "refused"
        → main/teams-audio-capture.ts: spawn the helper (no args, stdio pipes, env without secrets), wait for status=ready
        → stdout s16le 16 kHz → createPcmFramer (100 ms frames) → core/speech startMicSession (segmenter → WAV → Grok STT)
        → bee:teams-audio:lines { id, lines } (text only) → store actions.teamsAudioLines → teamsAudioEcho dedupe
        → addLines as "Meeting: …" → pipeline
  anything else (mic off, call over, setting off) → bee:teams-audio:stop → stdin closed → helper exits 0
  helper exits by itself → bee:teams-audio:ended { id, failure } → store: failed until the plan leaves "listen"
```

- **When.** `teamsAudioPlan`: setting on, platform supported, a Teams call and the mic on. Zoom and Google Meet never count. Main checks the same (`teamsAudioAllowed`, mic aside) before it starts the helper, and on every status poll while it runs.
- **No coverage check (simplification).** With client sync gone there is never a sync room, so no call is ever "covered" by teammates' Bees. The old `teamsAudioCoverage`, `namesMatch`, the `coverage` field of the status and the `covered` plan are removed. Coverage is always treated as `uncovered`: with the setting on, the mic on and a Teams call, Bee listens. It cannot tell who in the call has Bee, so it may also hear people who run their own Bee. The dedupe below still drops a phrase that repeats the user's own line or a caption.
- **Separate stream, in main.** Teams audio never goes into the mic's frames and never reaches the renderer. Main gives it its own segmenter and speech-to-text queue (`core/speech.ts startMicSession`, the mic's code), shows no "Got it…", and keeps its speech-to-text errors to a log code (the mic shows the same ones). A gap in the helper's audio (Teams silent) is filled with silence every 250 ms so a phrase in progress still ends. When the capture stops, queued phrases are dropped, not transcribed.
- **Dedupe** (`core/teams-audio.ts`, word Dice 0.6 via `echoesOwnLine`, 20 s). A Teams-audio phrase that repeats a recent own line or caption is dropped. A caption line that arrives later and repeats a recent Teams-audio line replaces it in the session (it names the speaker) and starts no turn of its own.
- **Indicator.** Bee does not advertise Teams audio. While a meeting is active (or Teams audio is listening), the pill and Live → Meeting say "Meeting in progress" (`notch.ts`, `meeting-notices.ts`); the old "Listening to you and Teams audio…" and "Listening to Teams audio for people without Bee." are gone. Settings shows a status line while listening ("Meeting in progress") or when something needs the user (`teams-audio-message.ts`): not available (Linux, OS too old, helper missing), needs Screen Recording (macOS, with **Open Screen Recording settings**), Teams app not found, this OS cannot share Teams' sound, or could not hear Teams. There is no "everyone has Bee" line.
- **Fail-open.** A capture that will not start (helper missing, OS refused, permission off, Teams not running, no `ready` in 10 s) or whose helper exits by itself stops and is not retried until the plan leaves "listen" (call over, mic off). A `refused` start (main's status moved on) is not a failure; the next tick decides again. The mic and the pipeline never wait for it. Main's status never throws: a detector failure reads as no call.
- **Lease.** The renderer's status poll (5 s) renews a 30 s lease. With no poll from a signed-in renderer for 30 s (window gone, signed out), main stops the helper and sends `ended` with no failure. At quit, main stops it too; a helper whose stdin closes (Bee died) exits on its own.
- **Privacy.** Audio stays in memory in main and is dropped once transcribed; only text crosses to the renderer (`teamsAudioLinesSchema`, 10 lines of 2000 characters at most per message). The helper gets Bee's environment without secret-looking variables. Logs carry codes and counts only (`teams-audio helper status=ready`, `teams-audio helper exit=5`, `teams-audio lines +1 total 3`, `teams-audio stt=err`); the helper's stderr is parsed for a status code and never logged. The helpers write no files.

## Processes and security

- The window is frameless, transparent, always on top and skipped from the taskbar. On first run it sits at the top centre of the primary display's work area. After that it keeps its position: each resize grows in place on the display the window is on, shifting only to stay inside that display's work area, and the last `{ x, y, displayId }` is saved in `settings.json` (main only) and restored at start-up. If that display is gone, it returns to the primary top centre. The maths is in `core/interface-scale.ts`. It resizes between 480 × 64 px (collapsed), 480 × 360 px (notch and island response) and 480 × 640 px (expanded).
- The renderer runs with `sandbox: true`, `contextIsolation: true` and no Node integration.
- The renderer is served from `bee://renderer/` by `protocol.handle` (`main/renderer-protocol.ts`), not `file://`, so Clerk sees a stable origin. In development the handler proxies to the Vite dev server. Paths outside `out/renderer` return 404.
- The same handler sends the content security policy as a response header. Fonts are bundled (Instrument Sans woff2 in `renderer/src/fonts`), so `default-src 'self'` covers them and no font hosts are allowed. Remote scripts are allowed only from the Clerk Frontend API host (derived from the publishable key: `clerk.vedantb.com`) and `challenges.cloudflare.com` (bot protection). Images are allowed from any `https:` host (Clerk avatars, and connector icons from `serverInfo.icons` or the Icon URL) and `data:` URLs.
- Links opened from the renderer are denied; `https://` links (Clerk terms, help) open in the system browser.
- Only the `media` permission (microphone) is granted. `display-capture` is denied and `setDisplayMediaRequestHandler` always refuses, so no page in Bee can capture the screen or all system audio.
- For a direct request ("Bee, open Teams"), main may run `/usr/bin/open -a <app>` (macOS) or agent-desktop's action runner, always with `execFile`, fixed arguments, no shell and no secret-looking variables. See [Talk to Bee](#talk-to-bee-wake-word). [Computer use](#computer-use) runs agent-desktop through its own allowlisted runner the same way; text the AI types is an argument after `--`, never a command.
- Main may start one child for Teams audio (`native/teams-audio`, see [Teams audio fallback](#teams-audio-fallback)): the Teams app's sound only, stdio pipes, Bee's environment without secret-looking variables, stopped by closing its stdin.
- All IPC input is validated with zod in main. All IPC output is validated with zod in preload.
- Secrets are encrypted with `safeStorage` before they are written. If encryption is unavailable, they stay in memory for the session.

## Authentication

Bee uses `@clerk/electron` against the vedantb.com Clerk production instance (`shared/clerk.ts`; `VITE_CLERK_PUBLISHABLE_KEY` overrides the key at build time).

- **Main:** `createClerkBridge` runs before `app.whenReady()`. It registers the `bee` scheme as privileged, owns Clerk's token-cache IPC, and takes the single-instance lock on Windows and Linux. Bee stops booting when `isPrimaryInstance` is false. Bee then swaps the bridge's two OAuth IPC handlers for its own (see **OAuth**). Tokens persist via `@clerk/electron/storage` (`electron-store` + `safeStorage`; not persisted without OS encryption).
- **Preload:** `exposeClerkBridge()` alongside `window.bee`.
- **Renderer:** `ClerkProvider` from `@clerk/electron/react`. Signed out, the panel shows `<SignIn>`; signed in, it shows the Bee panel with a `<UserButton>`. The microphone button shows only when signed in.
- **Pipeline gate:** the renderer sends `getToken()` with each run. Main checks the token's issuer (`https://clerk.vedantb.com`), subject and expiry. The signature is not verified: this is a sign-in gate, not a security boundary, since the pipeline only uses the user's own key and notes.
- **OAuth:** social sign-in returns the system browser to `http://127.0.0.1:45789/sso-callback` (`CLERK_OAUTH_REDIRECT_URL`), not to `bee://renderer/`. A browser cannot show a custom-scheme URL as a page, so with `bee://` the tab stayed on the provider's last page.
  - `main/clerk-oauth-ipc.ts` runs right after `createClerkBridge`. It removes the bridge's `clerk:oauth-transport:get-redirect-url` and `clerk:oauth-transport:open` handlers and registers its own, which answer only the main frame of a `bee://renderer/` window. The token-cache handlers stay. A test checks the channel names against the package's built channel table, since the package does not export them.
  - `get-redirect-url` returns the loopback URL. `open` accepts only an https URL (zod). It starts the server in `main/clerk-oauth-loopback.ts` (no Electron imports) on `127.0.0.1:45789`, then opens the URL with `shell.openExternal`. When the browser reaches `/sso-callback`, it resolves `{ callbackUrl }` (the `@clerk/electron` transport contract) and shows and focuses Bee's window (`app.focus({ steal: true })` on macOS).
  - The server answers with one self-contained page from `main/clerk-oauth-page.ts`: Instrument Sans and the logo inlined, light and dark, a CSP that allows only its hashed script, and nothing echoed from the request. It reads `__clerk_status` and `__clerk_error_code` to show **Signed in to Bee**, **Almost done** (sign-in handed over to sign-up), **Sign-in was cancelled** or **Sign-in did not finish**. Cancels and errors still resolve with the URL, so clerk-js shows the error in the panel. The page links to `bee://renderer/` (**Return to Bee**; main brings the window forward on `open-url` and `second-instance`), and removes the query from the address bar.
  - Other paths and methods get 404. One sign-in runs at a time and times out after 3 minutes. The server stops after each sign-in, timeout, failure or cancel, so the next sign-in starts clean. The port is fixed because Clerk needs the exact URL allowlisted.
  - The bridge's own `bee://` `open-url` and `second-instance` listeners stay registered but never see a pending flow. electron-builder still registers the `bee` scheme (`build.protocols`, plus the Linux MIME type) for **Return to Bee** and team invites.
- **Dashboard:** Native API must be enabled. The allowlist for mobile SSO redirect must hold `http://127.0.0.1:45789/sso-callback` as well as `bee://renderer` and `bee://renderer/*`.

### Why Jev does not use chat completions

The brief asked for Jev via the OpenAI-compatible `/v1/chat/completions` endpoint. On 26 September 2026 the Gateway rejected that call with `ModelTypeMismatchError`: "Model 'typesafe-ai/jev' is an evaluation model, not a language model. Use the evaluation generation API instead." The Gateway model list gives Jev `"type": "evaluation"`. Bee therefore calls Jev through the AI SDK evaluation API. To keep one client, Luna uses the same SDK.

### Jev prompt format

Defined in `src/core/jev.ts`.

- **State:** `{ transcript }`, the recent meeting lines joined by newlines, oldest first.
- **Questions:** one `score` question per candidate, keyed `c0`, `c1`, … in retrieval order. Each question's instructions carry the task, the note title and the note text:

  ```json
  {
    "type": "score",
    "instructions": {
      "task": "Rate how relevant this note is to what the meeting is discussing right now.",
      "noteTitle": "Acme renewal › Pricing",
      "noteText": "…"
    },
    "criteria": [
      "Irrelevant: unrelated to what is being discussed.",
      "Loosely related: same broad area, but not useful right now.",
      "Relevant: useful background for the current topic.",
      "Directly useful: answers or informs what is being discussed right now."
    ]
  }
  ```

- **Answer:** Jev returns a fractional score from 0 to 3 per question.
- **Ordering:** highest score first, with ties kept in retrieval order. Missing, wrong-type or out-of-range answers go last, in retrieval order.
- **Filter:** notes scoring below 1 (`JEV_MIN_SCORE`) are not sent to Luna. They still show in the panel.
- **Fail-open:** if the call throws, times out or returns no usable score, Bee keeps the retrieval order and reports `Jev ranking failed: <reason>` in the panel.

Question keys are positional (`c0`…) rather than note ids. Note ids contain characters such as `#` and `.`, and positional keys keep the mapping simple.

### Tools and sources
`src/core/tools.ts` holds the tool registry. `lunaTools()` returns the `ToolSet` passed to Luna. It always includes `web_search` (`anthropic.tools.webSearch_20250305({ maxUses: 3 })` from `@ai-sdk/anthropic`). It uses the basic version: the dynamic-filtering versions (20260209, 20260318) search from a code execution sandbox, and Haiku via the Gateway only ran `code_execution` there and never searched. Anthropic runs the search itself, so Luna calls that send it pin the Gateway to the Anthropic provider (`guideProviderOptions(tier, { web: true })` sends `only: ["anthropic"]`); bedrock or vertex may reject the tool. If the provider still rejects it, `guideWithLuna` retries once without `web_search`, with `order: ["anthropic"]` so the Gateway can fail over. Calls without web search (the meeting summary) also use `order`. The model decides when to search; Bee never forces it. Search runs in one provider-side step, and `sourcesFromGenerateResult` reads the links from `result.sources`, or else from the tool output (an array of `web_search_result` items). When `notesDir` is passed, the set also includes the four file tools below. New tools go into the same registry. `lunaTools({ notesDir, extraRoots, extra })` also takes `extra`, a `ToolSet` of MCP tools (see below). It stays synchronous; the caller loads MCP tools first. Built-in names win over an `extra` tool of the same name.

The file tools come from `src/core/fs-tools.ts` (`lunaTools({ notesDir })`); without `notesDir` they are omitted. They run in the main process (the pipeline does), so they use Node `fs`. They add to retrieval and Jev; they do not replace them.

| Tool | Does | Limits |
| --- | --- | --- |
| `list_dir` | Names, type and size in a folder; optional one level of subfolders | 200 entries; binaries marked `skip` |
| `search_files` | Case-insensitive match on file name or content; relative path plus a short line | 20 hits, 200-character snippet, 2000 files, depth 4 |
| `read_file` | Text of one file | 256 KiB file limit; 64 KiB returned, then truncated with a note |
| `append_note` | Creates or appends to a `.md` file | Notes folder only, file name only, 8 KiB per call, never overwrites |

Sandbox (`src/core/fs-sandbox.ts`): the only root is the notes folder. Other folders are for Claude Code's own tools on "Bee, …" requests; the old `fsRoots` setting is gone and ignored in old files. Relative paths start at the notes folder. Backslashes count as separators on every platform. A path is refused if it holds a NUL byte, is empty, or resolves (`node:path`) outside every root. All symlinks are refused, and so is any path whose real location leaves its root. Listings and searches skip dotfiles and symlinks. A file is binary if its extension is on the binary list or its first 4 KiB hold a NUL byte. Tools return a short `Error: …` string instead of throwing.

`sourcesFromGenerateResult` reads `result.sources` and, if that is empty, `output.sources` in `result.toolResults`. It keeps unique `https` URLs, falls back to the hostname for a missing title, and returns at most 5. `PipelineResult.sources` carries them to the renderer, which shows each as a link chip after the tips' links (`core/link-suggest.ts` `sourceChips`, merged in `store.ts`; deduped by domain, not personalised). There is no separate Sources list. The list is empty when there is no key or Luna fails. A failed search fails open: Luna still returns tips, or the usual `Luna guidance failed:` error.

### MCP servers (Connectors)

The user connects MCP servers in the **Connectors** tab, between **Live** and **Settings** (`renderer/src/Connectors.tsx`), so Luna can use their tools, for example vmem, Eva or a local command. There are no presets and no hard-coded URLs: the tab lists only saved servers, one row each with icon, name and **Connect** or **Disconnect**. An HTTP row with auth "none" runs Connect through `connectMcpServer` (MCP OAuth, see below) and counts as connected when enabled with tokens stored (`hasAuth`); other rows switch on and off. Disconnect removes the server with its tokens. **Add custom**, or a click on a row, opens the full form (name, transport, URL, optional **Icon URL**, auth, stdio, tool switches). Servers saved as the old vmem or Eva presets stay in `mcpServers` with the same `id`, so their tokens in `mcpSecrets` keep working, and show as ordinary rows. Two transports, both through the official `@modelcontextprotocol/sdk` (a runtime `dependency`, so it lands in `app.asar`):

Icons (MCP 2025-11-25 `serverInfo.icons`): after `client.connect`, `connectMcp` reads `client.getServerVersion()` loosely (`readServerInfo`) into `serverInfo: { name, websiteUrl?, iconUrl? }`. `pickServerIcon` (`shared/mcp-icons.ts`) keeps only `https:` and `data:image` srcs (at most 100,000 characters), prefers `theme: "dark"` (Bee is dark), then unthemed, then light, and within a theme the `sizes` nearest 32px (`any` counts as a fit). The pool's cache entry carries `serverInfo`, so `testMcpServer` returns it, and `mcp-ipc.ts` saves it on Test and after sign-in through `settings.mcpRecordTools(id, tools, serverInfo)` as `serverInfoName`, `websiteUrl` and `iconUrl`. Tokens are not touched. A row shows, in order: the user's `iconOverride` (Icon URL; https or `data:image`, checked again in `mcpSave`), the stored `iconUrl`, the favicon of `websiteUrl`'s host, the favicon of the connector URL's host (`faviconHostOf` skips `*.convex.site`, which serves none), then the first letter of the name (`@vvedantb/ui` `Avatar`, `AvatarImage`, `AvatarFallback`). Favicons come from `bee:favicon:get` (`createFaviconResolver`) as data URLs; https connector icons from `bee:icon:get` (`createHttpsImageFetcher`). The renderer CSP still blocks remote images, so both paths hand data URLs to the UI.

- **Streamable HTTP** (`StreamableHTTPClientTransport`): `https`, or `http` on localhost only. Auth is none, a bearer token (`Authorization: Bearer …`) or a custom header (name plus value).
- **stdio** (`StdioClientTransport`): command, args (one per line, or space-separated) and env `KEY=value`.

Custom connectors can still paste a bearer token or header. Remote servers with auth "none" sign in with MCP OAuth, described below.

`src/core/mcp.ts` (no Electron imports) connects, lists tools and calls them. `loadMcpTools(configs)` connects to every server at once and wraps each enabled tool as an AI SDK `tool()` named `{prefix}__{tool}`. The prefix is the server name cleaned to `[a-zA-Z0-9_-]` (24 characters at most, no `__`) and lowercased, so a server named "Eva" has tools `eva__…`; names are capped at 64 characters and made unique. It also returns `servers` (`{ name, prefix, toolCount }` for each server that listed, counting only tools left switched on) and `errors`. A server listing more than 100 tools (`MCP_MAX_TOOLS`) keeps the first 100, and main warns with the server name and how many were dropped. Connect and list time out after 10 s, each call after 15 s. A server that fails or hangs is skipped (main logs its name and a short reason, never secrets), so the others still load. A tool call that fails returns a short `Error: …` string; it never throws into `generateText`. Error text has every secret value masked.

`runPipeline` calls `loadMcpTools` (passed in by `registerMeetingIpc`, which reads enabled servers and decrypted secrets from settings on each run, like `fsRoots`) only when Luna is about to run, hands the tools, `servers` and `errors` to `guideWithLuna({ extraTools, connectedServers, unavailableServers })`, and closes every connection (and stdio child process) when the run ends. For vmem (`isVmemConnector`, from the stored `serverInfoName`, passed on `McpServerConfig`), Luna gets only the tools in `VMEM_TOOL_ALLOWLIST` (`core/mcp.ts`: memory, artifact and file read and search tools such as `memory_search`, `artifacts_get` and `files_list`, 10 of vmem's 94, which saves some 25k tokens a turn); `toolCount` counts only those, and if vmem lists none of them all its tools stay. Other connectors send every enabled tool. `settings.mcpConfigs()` leaves out enabled sign-in servers (HTTP, auth "none") with no stored tokens; `settings.mcpSignedOut()` names them and `registerMeetingIpc` adds them to `errors` as "not signed in". When any server is connected or unavailable, `lunaMcpSystem` adds an MCP block to the system prompt that names them, for example "Bee connectors connected now: vmem (77 tools, named vmem__<tool>), Eva (84 tools, named eva__<tool>)." and "Not available this turn: X (reason)." Luna answers "what is connected" from that list, and is told that a server's own tools such as `connectors_list` describe that service's data sources, not Bee's connectors. Tool-name examples use the real prefixes. It still says to call the tools before guessing about the user's data, and never to invent a result. A schema error drops the tools it names and retries; a tool-count error ("array too long") drops every MCP tool at once. After a drop, each server's count is recomputed and a server left with no tools is listed as unavailable ("tools skipped after a schema error"). `PipelineResult.mcpErrors` (at most 20, short reasons, never secrets) reaches the Live tab as one muted line (`mcpErrorNote` in `renderer/src/island.ts`), for example "Eva unavailable: sign in again from Connectors".

MCP sign-in (OAuth): vmem and other remote servers with auth "none" use standard MCP authorization through the SDK. `core/mcp-oauth.ts` (no Electron imports) wraps the MCP client helpers in `@vvedantb/server` (a runtime `dependency`, so it lands in `app.asar`) with Bee's options; it keeps the stored state schema local. The provider implements `OAuthClientProvider` over injected storage and an injected `redirectToAuthorization`: client name "Bee", `token_endpoint_auth_method: "none"`, authorization code with PKCE, dynamic client registration, refresh tokens. `authorizeMcpServer` connects first; on 401 the SDK reads the protected resource metadata (RFC 9728, from `WWW-Authenticate` or `/.well-known/oauth-protected-resource`), then the authorization server metadata, registers a client and opens the system browser (`shell.openExternal`, http(s) only). The redirect is a one-shot HTTP server on `127.0.0.1` with a random port (`main/mcp-oauth-loopback.ts`, the package loopback with Bee's page texts, path `/callback`, `state` checked, five-minute limit). It is not `bee://`, which Teams invites use, and not the fixed port 45789 that Clerk sign-in uses (`main/clerk-oauth-loopback.ts`). That exact URL is registered in `redirect_uris`, so a saved client is registered again when the port differs. Tokens and client information are stored encrypted in `mcpSecrets` and refreshed automatically (the SDK refreshes on a 401 and the provider saves the result). `bee:mcp:authorize` runs the flow for a server id, then lists tools, saves them and switches the server on. Every HTTP provider, interactive or not, has `saveClientInformation`, so the SDK never fails with "OAuth client information must be saveable" on a 401 that advertises dynamic registration. Luna and link chips get a provider that still never opens a browser (`createMcpOAuthProvider` without `redirectUrl`: `redirectToAuthorization` rejects with "Sign in from the Connectors tab"), so a missing or expired sign-in fails open. Tokens never leave main.

Personalised links use the same client. `isVmemConnector` (`shared/mcp-names.ts`) matches a server whose stored `serverInfoName` (the `serverInfo.name` it reported in MCP initialize) slugs to `vmem`, ignoring case. It never reads the display name or URL host. Servers saved before Bee stored `serverInfoName` get one once at settings load (`legacyServerInfoName` in `main/settings.ts`): `vmem` or `Eva` when the display name slugs to `vmem` or `eva`, or when the URL is on a former preset host (`vmem.vedantb.com`, `vmem.projectv.uk`, `eva.vedantb.com`, the Eva Convex site). The file is rewritten only if something changed; ids and `mcpSecrets` are kept. After that, the name the server reports on the next Test or sign-in replaces it, and a URL change clears it. Callers check `enabled`. `settings.vmemConfig()` returns it with its secrets, and `settings.linkSettings()` returns `{ enabled, hasVmem }`. The `personalisedLinks` setting defaults to whether such a server is enabled. `core/vmem-history.ts` (`createVmemSearch`) keeps one warm `connectMcp` connection: opened at app start when the connector is enabled and signed in, and on each save, remove, enable or sign-in (`refresh()`), closed on Disconnect and at quit. A search picks `memory_search` (else `search`, else a tool with "memory" and "search" in its name) and calls it once per source (`browsing-history` and `bookmark`, or the matching values of an enum) with a 1 s limit each, then merges the results, so a chip pays for the call and not for connecting. A cold connect (5 s limit) runs in the background and a chip that has to wait is cut off by the 2 s enrich budget (`ENRICH_TIMEOUT_MS`). A failure other than a timeout drops the connection so the next search reconnects. `parseHistoryHits` reads the text or JSON output without a schema: it tolerates missing fields, and returns `[]` for anything unreadable. Without a connector, or on failure, history is `[]` and Jev still scores the plain domain chip. `createLinkEnricher` takes an `onFallback(reason)` callback; `link-ipc.ts` logs it with `console.debug("Bee: personalised links fell back:", reason)`, and unexpected MCP errors with `console.warn`.

Storage (`main/settings.ts`, `settings.json`):

- `interfaceScale`: the Interface size in Settings, one of 0.9, 1 (default), 1.1, 1.25, 1.5, 1.75. Anything else on disk reads as 1, and a save accepts only those values. Main applies it with `webContents.setZoomFactor` on every window and scales the overlay bounds by the same factor (`core/interface-scale.ts`), keeping the current window mode. It takes effect on save, like meeting mode.
- `mcpServers`: `{ id, name, enabled, transport, url?, command?, args?, envKeys?, auth: { type, headerName? }, tools?: { name, description, enabled }[], serverInfoName?, websiteUrl?, iconUrl?, iconOverride? }`. A bad value in one of the last four reads as unset and never drops the list. At most 20 servers and 100 tools each, validated with zod. Names must be unique after slugging. An invalid list is dropped without losing the other settings.
- `mcpSecrets`: one `safeStorage` ciphertext (base64) of JSON keyed by server id, holding the bearer token or header value, the stdio env values and, for OAuth servers, an `oauth` blob (tokens and client information, each stamped with its authorization server by the SDK). Secrets are never written into `mcpServers`. If encryption is unavailable they stay in memory for the session, like the gateway key.
- `view` objects carry `hasAuth` and env key names only. On save, a secret that is omitted stays as it was and `""` clears it. Changing the auth style drops the old secret.

IPC (`main/mcp-ipc.ts`, zod in main, parsed again in preload): `bee:mcp:list`, `bee:mcp:save`, `bee:mcp:remove`, `bee:mcp:set-enabled` (a server, or one tool), `bee:mcp:authorize` (sign in; see below) and `bee:mcp:test`. Test connects, lists, saves the list (a known tool keeps its switch, a new tool starts on) and returns `{ ok, tools?, error? }`. The Settings list shows each server's tools with a per-tool toggle.

### Luna prompt format

Defined in `src/core/luna.ts`. The system prompt asks for a few short tips (the cap is in the message tail), one per line, under 20 words each. If the latest lines ask a direct question, the first tip answers it: from the notes when they cover it (cited as `[n1]`), otherwise from general knowledge, with a brief caveat when the answer may have changed since training. Otherwise tips suggest what to say next, citing notes. Tips must not invent facts about the user's own work. If there is nothing useful, the model replies `NONE`. If the notes do not cover a question and the fact is public or may have changed (office holders, news, scores, prices), Luna calls `web_search` and may end the tip with the site domain; a `[web]` tag the model still adds is stripped (`parseLunaTips`). A follow-up ("why…") gets its own answer: on a new turn the latest settled tips go to Luna as context (`earlier`, after the transcript), not on screen. It does not search for stable facts or sums. If the notes do not cover a question about the user's own notes or files, Luna uses `list_dir`, `search_files` and `read_file` (injected `[n1]` notes first, never `web_search` for private facts), and calls `append_note` only when the user clearly asks to add or save a note. The user prompt holds the last 8 transcript lines and the notes labelled `[n1]`… The panel shows the same labels next to each note.

Prompt caching: `buildLunaPrompt` returns the parts in cache order, and `lunaRequest` sends them with explicit Anthropic cache breakpoints (`ANTHROPIC_CACHE` in `core/gateway.ts`; not the Gateway's `caching: "auto"`). The system (`LUNA_SYSTEM`, the MCP block, the meeting rules) is the same on fresh and steering turns and carries the first breakpoint. The user message has three text parts: the context (meeting brief and notes, second breakpoint), the transcript window (no breakpoint: it slides every phrase), and the tail (shown tips, the tip cap of 2 or 3, `LUNA_STEERING_RULES` while tips are kept, and the `Tips:` cue). A prefix under Anthropic's minimum cacheable length is not cached. `guideWithLuna`'s `onFinish` and the `perf luna` line report cache read and write tokens. The summary call puts the breakpoint on its system message.

### Summary prompt format

Defined in `src/core/summary.ts`. The system prompt asks for exactly three `##` sections (Decisions, Action items, Topics) of short bullets, action items as `- Owner: task` when an owner is named, `- None recorded.` for an empty section, and no facts beyond the transcript and notes. The user prompt holds the session transcript and the titles of the notes cited. `parseSummaryMarkdown` drops code fences, titles and preamble, and rejects a reply missing any section.

## Renderer state

One small external store (`renderer/src/store.ts`, read with `useSyncExternalStore`) holds settings, the active tab, the meeting session (not rendered), the last result, the summary state, the microphone state, the update state and whether a meeting is active. A `setInterval` outside React drives the 5 s meeting, detection and Teams audio ticks. Forms are uncontrolled and read with `FormData` on submit. There is no `useEffect`. The React Compiler is enabled.

Saved secrets show as a disabled field reading `•••••••• (saved)` with **Replace**. The form remounts after a successful save, so typed secrets clear and saved fields go back to masked.

## UI

- Font: Instrument Sans (variable, 400–700), self-hosted woff2 with the SIL OFL licence alongside.
- Icons: `@tabler/icons-react` (bundled into the renderer; unused icons are tree-shaken).
- Island: the notch is a pill. While a run is busy it shows the tool Luna is using (`bee:luna:activity`, `{ runId, tool, phase: "start" | "end" }`, sent from main by `guideWithLuna` from the stream's tool parts, so provider-run `web_search` shows as it starts, plus `onToolExecutionStart`/`End` and an `onStepFinish` fallback, deduped per call; the store keeps the run's calls in flight in `tools`; `activityLabel` maps `web_search` to "Searching the web", the file tools to "Reading notes", `append_note` to "Writing a note", an MCP tool named `prefix__tool` to "Using prefix…", anything else to "Thinking…"). When the answer arrives, the same surface grows downward with the tips (17 px) and link chips, search sources included. The body closes with the × button, or folds back to the pill's one line after `islandOpenMs` (30 s plus 1 s per 3.3 words shown) with no new result, scroll, busy run or pointer on the island. Opening the full panel cancels the timer. A new result reopens the body. Clicking the one-line answer in the pill opens it in full in the island (`fullText`, window size `response`), never the panel. Like any answer, it opens at the top: the body never scrolls by itself, so the user reads from the first line. It stays until the × button, a click outside the island or a new turn. Only the chevron opens the panel. A line starts a new turn (the last answer goes, nothing is kept) unless it interrupts a busy run (`core/steering.ts` `isNewTurn`). A run answering a question is not cancelled by later lines that are not questions; they wait for it (`waitsForRun`). The body does not show while the panel is open. Tips are not streamed: `generateText` returns them whole, so the finished tips fade and slide in.
- Logo: `renderer/src/BeeLogo.tsx` is an inline SVG honey orb with two stripes, glassy wings, antennae and pill eyes. It sits at the start of the notch (20 px, in place of the old dot) and above sign-in. `logo.ts` picks detail by size: below 24 px it drops the glow, antennae and catchlights and crops the view. `tone` is the background: `"dark"` (default, the app's surfaces) draws white glassy wings; `"light"` draws them grey (#d4d4d8 to #cfcfd4) with a #8a8a92 outline so they read on white. It blinks every 3–5 s (phase per instance). In the notch, `notch.ts` `logoState` picks one of seven states (error > searching/tool > thinking > done > listening > idle), each with its own motion and extras (mic-level ring, orbiting dots, figure-8 with magnifier, honeycomb, a one-shot loop and sparkle for `LOGO_DONE_MS`, drooped grey wings with a red dot); path keyframes are generated in `logo.ts`. The animated 20 px view widens to `5 5 54 54` so extras fit. With motion off each state holds a still pose. `animated={false}` renders the plain static mark. `resources/bee-logo.svg` and `bee-logo-light.svg` are the two tones at 512 px, kept in step by file snapshots in `logo.test.ts` (`npx vitest run -u` rewrites them).
- Icons: `npm run icons` (`scripts/make-icons.mjs`) bundles `BeeLogo` with esbuild, renders it with `@resvg/resvg-js` and writes every icon; commit the output. The app icon is the dark-tone mark on a warm dark tile (#2b241a to #110f0b, Bee's surface colour, so the orb glows as in the notch), drawn again at each size so small sizes get the simple mark. macOS (`icon.icns`, master `icon-mac.png`) follows the Big Sur grid: an 824 px superellipse tile with a drop shadow in a 1024 px canvas. Windows (`icon.ico`, 16–256 px) and Linux (`icon.png`, 512 px) use the tile with a 3 % margin and no shadow. The macOS tray loads `trayTemplate.png` (16 px, hand-placed pixels) and its `@2x` sibling (32 px): a black-and-alpha side-on bee (teardrop body with stinger and two stripes, round head, two fanned wings, no face) that the menu bar tints. Windows and Linux load the colour `tray.png` (32 px, light tone, as taskbars may be light or dark). The site gets `docs/icon.png`, `docs/favicon.ico` and the light-tone mark as `#i-mark` in `docs/index.html`. They stay out of `app.asar` (`build.files`) except the tray PNGs, which main reads at run time. `scripts/make-icons.test.mjs` checks that the build config points at icons that exist and that the tray sizes are right.
- Motion: CSS only, 150–220 ms, transform and opacity. Panel slides in on expand and fades out before the window shrinks (`COLLAPSE_MS` 160 in the store matches the CSS). Tabs, notch status, tips and notes fade or rise in. `prefers-reduced-motion` turns motion off.

## CI

`.github/workflows/ci.yml` runs on every push and pull request. A `windows` job builds the Teams audio helper (`npm run build:teams-audio:win`: fails if it does not compile or answer `--version`), runs `npm run typecheck` and `npm test`, packages an unpacked app (`electron-builder --win dir`) and checks `resources/teams-audio/teams-audio-helper.exe` is in it and answers `--version`. A `macos` job builds both Teams audio helpers (arm64 and x64, checked with `lipo`), runs `npm test`, `npm run build`, the replay E2E and an unsigned `electron-builder --mac dmg zip --arm64 --x64`, checks each `Bee.app` carries its own arch's helper and that the arm64 one answers `--version`, then uploads the artifacts. No job joins a Teams call. `release-windows.yml` ("Release") builds Windows and macOS in parallel, with the same helper builds and packaged-helper checks; a final `publish` job downloads both and makes the one GitHub release.
