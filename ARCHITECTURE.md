# Architecture

Bee is an Electron app built with electron-vite, React and TypeScript.

```
src/
  main/       Electron main process: notch window, tray, IPC, settings (including MCP servers), notes folder, bee:// protocol, Clerk bridge, Teams detector and sync IPC,
              experimental meeting window reader (agent-desktop runner), Teams audio helper process and its speech-to-text
  preload/    Sandboxed bridge: exposes window.bee (parses every response with zod) and Clerk's bridge
  renderer/   React UI: island (pill and response body; island.ts holds its pure logic), sign-in, expanded panel (Live, Settings), mic capture (mic.ts)
  shared/     IPC channel names and zod schemas, Clerk config (shared/clerk.ts)
  core/       Pure TypeScript: note chunking, retrieval, Jev ranking, Luna guidance and meeting summaries, MCP client and tool wrapping (`mcp.ts`), Grok STT, phrase detection and WAV
              (`speech.ts`, shared by the mic and Teams audio), pipeline, release version checks, Teams mode (relay protocol and client, sync controller, room ranking, detection debounce
              and heuristics, line merging), Teams audio fallback (`teams-audio.ts`) and its helper protocol (`teams-audio-protocol.ts`)
native/       Teams audio helpers (native/teams-audio): C++ for Windows (WASAPI process loopback), Swift for macOS (ScreenCaptureKit). Built in CI, not committed
relay/        Bee relay: shared HTTP handler + state + JWKS (Convex HTTP in convex/; in-memory mock for tests)
test/         Live Gateway smoke test (npm run test:gateway), Electron mic, summary and Teams E2E (npm run test:e2e, harness in test/e2e)
resources/    App and tray icons (generated by scripts/make-icons.mjs), entitlements
```

## Flow

```
Mic on (renderer/mic.ts)                           getUserMedia → ScriptProcessorNode, 4096-sample frames
  → renderer/speech.ts                             level meter; phrase detection; 16 kHz WAV
  → window.bee.transcribe({ audio, sessionToken }) preload → IPC
  → main/meeting-ipc.ts: check session, read key
  → core/transcribe                                Grok STT (xai/grok-stt) → text, or null for no words
  ↓
simulateLine(text)  ← also "Simulate meeting line" (Manual test)
  → Clerk getToken()                               no session → "Sign in to Bee"
  → window.bee.runPipeline({ transcript, sessionToken })   preload → IPC
  → main: check session token (main/auth.ts)
  → main: load notes, read API key                 key never leaves main
  → core/retrieve   BM25 keyword search, top 5 snippets
  → core/jev        Jev scores each snippet, re-orders (fails open)
  → core/luna       Luna (Claude Haiku 5.5) writes up to 2 tips from the top 3 notes, and may search the web
  → PipelineResult back to the renderer
```

The renderer keeps the last 8 lines (spoken, typed or from synced teammates) and sends them with each run. The lines are not rendered: the Live tab shows tips and notes only, plus web sources when a tip cites them. Apart from the Teams sync state (below), the main process holds no meeting state.

## Meeting summary

```
End meeting & save summary (Live tab)
  → store.endMeeting()                              stops the mic; session cleared for the next meeting
  → window.bee.writeMeetingSummary({ transcript, notesCited, tips, sessionToken })
  → main/meeting-ipc.ts: check session, read key
  → core/summary                                    Luna writes Decisions / Action items / Topics (fails open)
  → main/notes.ts writeMeetingSummaryFile          <notes>/meeting-YYYY-MM-DD-HHmm.md
  → { path, usedLlm, error } → "Open summary"      main opens it only if it is a .md directly in the notes folder
```

- **Session** (`renderer/src/store.ts`): the store keeps every line since the last saved summary (up to 200, `SESSION_TRANSCRIPT_MAX`) as `SessionLine { id, own, speakerId, speakerName, text, clientTs, serverTs }`, merged by spoken time (`core/sync-lines.ts`). It also keeps the titles of notes cited in shown results and the tips shown (up to 100 each). The pipeline window is the last 8 session lines, teammates' lines as `Alice: …`. None of it is rendered. If saving fails, the session is restored.
- **Speakers**: a solo session is sent as plain strings (the original path). Once any teammate's line is present, every line is sent as `{ speaker, text }`, own lines under your team display name. `core/summary.ts` then writes `Speaker: text` lines, adds speaker rules to the system prompt (attribute owners by speaker; only Bee members are captured) and adds a `## Speakers` section with a partial-transcript note.
- **File**: `# Meeting summary — YYYY-MM-DD HH:mm` (local time), then `## Decisions`, `## Action items` (owner first when named), `## Topics`, `## Notes cited` and, if any, `## Tips shown`. Bee writes the title, notes cited and tips itself; the model writes only the first three sections. A second summary in the same minute gets `-2`, `-3`… Nothing is overwritten.
- **Recall**: the file is an ordinary note. `chunkNote` splits it into one snippet per `##` section, so next week's "last time we discussed X" retrieves it like any other note.
- **Fail-open**: with no key, or if Luna fails, times out or replies without the three sections, Bee writes a plain summary instead: the same headings, "Not extracted" under Decisions and Action items, and the transcript lines under Topics. The meeting is never lost, and the UI says the summary was saved without AI and why. Real failures (sign-in, disk) show as errors and keep the session.
- The spoken transcript is still never shown on screen. It goes to disk only in the plain summary, inside the user's notes folder. Each run takes a number (`latestRun`); a result is shown only if no newer run has started, so fast speech never shows stale tips.

## Speech-to-text

Production uses **Grok STT** (`xai/grok-stt`) through Vercel AI Gateway, batch mode (`experimental_transcribe`). The Gateway model list names it `spacexai/grok-stt`; on 26 September 2026 both ids returned the same transcript, and Bee uses `xai/grok-stt`. Bee does not use the Web Speech API: in Electron it could not reach Google's speech service and failed with `network`.

- **Capture** (`renderer/src/mic.ts`): mono `getUserMedia` with echo cancellation and noise suppression, into a `ScriptProcessorNode`. No AudioWorklet, so no extra module under the CSP. Frames are about 85 ms at 48 kHz and also drive the level meter. The mic is the only stream, and nothing is mixed into it. Bee used to mix in screen plus `loopback` audio (all system audio) through `getDisplayMedia`; that is removed.
- **Who Bee hears**: the user's mic (above; shared with a Teams sync); teammates' own Bees through the relay (`teamsTick` → `addLines`, see [Teams mode](#teams-mode)); live captions read from the call window ([meeting window reader](#meeting-window-reader-experimental), never shared); and the [Teams audio fallback](#teams-audio-fallback), the Teams app alone through a native helper on Windows and macOS (never shared). Captions and Teams audio join the session as `Speaker: text` or `Meeting: text`.
- **Phrases** (`core/speech.ts`, no window, React or Electron imports; `renderer/src/speech.ts` re-exports it): a frame at or above RMS 0.01 counts as speech. A phrase starts with 300 ms of pre-roll and ends after 800 ms of silence, or at 15 s. Phrases with under 300 ms of speech are dropped. On mic off, the phrase in progress is still sent.
- **Upload**: each phrase is encoded as 16 kHz 16-bit mono WAV (about 32 KB a second) and sent over IPC. Main rejects payloads over 2 MB.
- **Order**: phrases are transcribed one at a time, so lines reach the pipeline in the order they were spoken.
- **Output**: text is whitespace-normalised. Empty or punctuation-only results (a cough or a click) count as no words and do not run the pipeline.
- **Errors**: a failed call returns `Speech-to-text failed: <reason>`. The mic stays on, the notch and the Live tab show the message, and it clears after the next successful phrase.
- **Mic hints** (`renderer/src/hints.ts`, no window or React imports): with the mic on and **Settings → Mic hints** on (`hintsEnabled`, on by default), the island shows one calm muted line when the input is near silent for 25 s, the voice stays quiet or too loud for 5 s, or four phrases in a minute come back with no words. One hint at a time; it hides after 15 s and that hint waits 4 minutes before it can show again. Built from frame levels and phrase outcomes only: no audio or words are kept or logged, no AI is called, and a hint is never a mic error. Thresholds are untuned first guesses.

Streaming (`experimental_streamTranscribe`) was not used. Phrase-level batch calls are simpler, and one call per phrase matches one pipeline run per line.

## macOS

- **Overlay.** On macOS the window is a `panel` and stays visible on all workspaces and over full-screen apps. The Dock icon is hidden (`app.dock.hide()` and `LSUIElement`). The tray is a template-image menu bar extra; it has no click handler, so it does not fight its menu. Windows and Linux keep click-to-toggle.
- **Shortcut.** `CommandOrControl+Shift+Space` toggles the window through `globalShortcut`. Failure to register is logged. It is released on `will-quit`.
- **Audio.** The mic (`getUserMedia`) is the only capture in the window. Main asks for microphone access at start-up on macOS and allows only the `media` permission. `getDisplayMedia` is always refused. The [Teams audio fallback](#teams-audio-fallback) runs a native helper (ScreenCaptureKit filtered to the Teams app), which needs Screen Recording for Bee; Bee never asks for it during a call (Settings has the button).
- **Packaging.** `build.mac` makes separate arm64 (Apple Silicon) and x64 (Intel) dmg and zip files with hardened runtime and the plists in `resources/entitlements.mac*.plist`. Unsigned by default.

## Updates

`main/updater.ts` and `core/release.ts`. No `electron-updater`: v1 downloads the installer by hand. On macOS it picks the `.dmg`, never the zip.

1. At start-up (and on **Check for updates**), main fetches `https://api.github.com/repos/vvedantb/bee/releases/latest` (10 s timeout) and compares its tag with `app.getVersion()` (major.minor.patch).
2. It picks the platform installer: Windows `*Setup*.exe` (NSIS), macOS `.dmg`, Linux `.AppImage`. Only URLs under `https://github.com/vvedantb/bee/releases/download/` are accepted.
3. **Download update** saves it to the temp folder as `Bee-update-<version>.<ext>` (our name, never the asset name) and checks the byte count.
4. **Quit & install** opens the file with `shell.openPath` and quits. The one-click NSIS installer replaces Bee and relaunches it. On Linux Bee shows the file in its folder instead.

Failures (offline, HTTP errors, no release, no asset) come back as values and show in Settings. A 404 means no release is published. The renderer never sees a download path.

## Teams mode

Bee never joins the call and uses no Microsoft identity (no bot, no Teams local API, no Graph or calendar). Teammates' Bees pool their own mute-gated mic phrases through the Bee relay. Without a Microsoft meeting id Bee cannot tell two concurrent meetings apart, so grouping is by explicit click only: timing and presence rank the choices, and membership is whoever clicked.

Concurrent meetings are surfaced, not guessed. The detector also lists each desktop meeting window by title (`meetingWindows`, deduplicated by normalised title). With two or more, the popup first asks **Which meeting?** (`selectMeeting`) and offers no one-click sync. If two or more syncs share the top rank (two invites, or two live recent syncs), `rankRooms` sets `ambiguous` and no `primary`, and the popup lists them all as equal choices. The pick binds this detection to that window title (`attached` in the controller; a sole window is bound on join or start). Other windows are ignored until the session ends. If the bound window is gone for the 15 s leave debounce, Bee leaves the sync and shows no new popup until the detection ends, even if other meeting windows stay open. A mic-only call (no meeting window title) behaves as one unnamed meeting and uses the boolean debounce only. Nothing is sent to the relay about windows; presence stays a boolean.

```
main/teams-detector.ts  (Windows: tasklist window titles + mic privacy registry; others: none)
  → core/meeting-tracker   raw reading → stable after 10 s; leave after 15 s false; new epoch per meeting
  → reading.meetings (window titles) → controller: 2+ unbound → "Which meeting?"; bound title gone 15 s → leave
renderer store: tick every 2 s → window.bee.teams.tick(token) → main/teams-sync.ts → core/sync-controller
  → relay GET /v1/me (every 60 s), PUT /v1/presence (on change, heartbeat 20 s)
  → in a sync: GET /v1/rooms/:id/phrases?after=seq  → teammates' lines → store mergeLines → pipeline + session
  → popup open or in a sync: GET /v1/rooms (rooms + presence) → core/room-picker rankRooms / inviteRoster / mergeCandidate
  → TeamsView back: prompt (meetings + selectedMeetingKey, Join "Alice, Bob" / Start new / Other syncs / Join by code,
    or an equal list when ambiguous), room, roster, merge, errors
Popup click → window.bee.teams.act({ type: "joinSync" | "startSync" | … }) → relay POST /v1/rooms[/join]
Mic phrase → store.simulateLine(text, "mic") → pipeline, and window.bee.teams.publish → shouldShare gate → POST phrases
  → relay stamps speakerId / speakerName from the verified Clerk JWT, serverTs, clamps spokenAt
Teams leaves the call (15 s) → controller leaves the sync; next detection → new popup, never an automatic rejoin
```

- **Relay** (`relay/src` + `convex/`): `handler.ts` routes HTTP to `state.ts` over a string key-value store. Production (`convex/http.ts`) verifies Clerk JWKS then runs `relay.dispatch` against a Convex `kv` table; `memory.ts` runs the same handler over a `Map` for tests and `npm run relay:mock`. `jwt.ts` checks RS256 against the Clerk JWKS (cached 10 min), then `iss`, `exp`, `nbf` and optionally `azp`. Unauthenticated or bad tokens get 401.
- **State**: `team:<id>`, `invite:<code>`, `user:<userId>` (membership, persisted); `presence:<teamId>`, `rooms:<teamId>`, `room:<id>`, `roomcode:<teamId>:<code>`, `phrases:<roomId>` (ephemeral). Rooms close when empty or after 4 hours; members that stop polling for 60 s are dropped; phrases are deleted with the room.
- **Room ids** are `crypto.randomUUID()`. Word codes are two random words, unique within the team while the room is open.
- **Ranking** (`core/room-picker.ts`): invited rooms (newest first), then rooms started within ±10 min of my detection with a member whose presence says "in a meeting" and is under 60 s old (closest first), then the rest. Only the first two tiers can be the one-click default.
- **Merge**: another room started within 30 s of mine by a teammate in a meeting. Each room votes (`POST …/merge`); when both have voted, the later room's members move to the earlier room and the later room is marked `mergedInto`.
- **Clocks**: every relay response carries `serverNow`. The client keeps the lowest-round-trip offset of the last 8 calls. It publishes `spokenAt` in server time and converts teammates' phrases back to its own clock, so lines merge in spoken order.
- **Share gate** (`core/sync-lines.ts shouldShare`): mic phrases only, only in a sync the user joined, never while **Pause sharing** is on. Teams' own mute is not readable without the Teams local API, so it is not used.
- **People without Bee.** A sync carries only Bee members' own mic phrases. Others are heard only through live captions (meeting window reader) or the [Teams audio fallback](#teams-audio-fallback), which uses the sync's members and the call window's roster to decide whether anyone is missing. Neither is ever published to the sync.
- **Fail-open**: relay errors never throw into the UI. Unreachable, 401 or 5xx shows "Bee is working solo" and the local pipeline carries on; 403/404 on a room ends the sync locally.
- **Main holds the relay connection**, so the renderer CSP stays closed to the relay host. The renderer passes a fresh Clerk token with each call; main checks it with `assertSignedIn` and the relay verifies it properly.
- **Window**: a third size, `prompt` (480 × 330), shows the notch and the sync card without the panel.
- **Island size**: a fourth size, `response` (480 × 360), shows the pill and the island body. `applyWindowSize` picks `expanded`, then `prompt`, then `response`, then `collapsed`.
- **Deep links**: `bee://team/XXXX-XXXX` in `argv` (first launch, `second-instance`) or `open-url` (macOS) fills the invite code in **Settings → Team**. The user still clicks **Join team**.

## Meeting window reader (experimental)

Settings → Meeting context → **Experimental: read meeting window** (`readMeetingWindowEnabled`, off by default). With it on, Bee uses [agent-desktop](https://github.com/vercel-labs/agent-desktop) (npm `agent-desktop`, Apache-2.0) to read the accessibility tree of the call window on macOS and Windows. It is read-only and headless: Bee runs only `permissions`, `list-apps`, `list-windows`, `find --count` and `snapshot`, never `--headed`, never a command that clicks, types, focuses or moves anything. `assertReadOnly` (`core/agent-desktop-envelope.ts`) refuses anything else before a process starts, and a unit test scans the source for agent-desktop calls.

```
main/meeting-window-reader.ts   (no Electron imports; polled by the meeting tick, the Teams tick and meeting context)
  permissions (macOS Accessibility) → list-apps (bundle ids, every 60 s) → list-windows (every 3 s at most)
  → core/agent-desktop-meeting detectMeetings: Teams (isMeetingTitle, or a plain name confirmed by find --role button --name Leave --count),
    Zoom ("Zoom Meeting", "Zoom Webinar", "Participants (N)"), Google Meet (browser window title "Meet - …")
  → main/teams-detector withMeetingWindow: merged with the built-in Windows reading (either says in a meeting; meetings deduplicated by key)
  Teams or Zoom call window: snapshot --compact --max-depth 25 → roster names (extractParticipants) and caption lines (extractCaptionLines)
  → captionStep (dedupe) → bee:meeting-window:captions → store.captionLines → addLines like teammates' lines → pipeline
runPipeline: meetingWindowBrief (name and people) joins the meeting brief; meetingTerms boosts retrieval (core/retrieve.ts)
```

- **Detection.** The built-in detector keeps running; the reader adds Teams, Zoom and Meet on macOS and Windows. `read()` never waits for agent-desktop: it returns the last reading (under 20 s old) and refreshes in the background. Meet is found only when its tab is the window's active tab (the window title is all Bee reads from a browser).
- **Context.** Teams and Meet titles name the meeting (Zoom's never do). People come from a roster region (Participants, People, In this meeting) in the call window, cleaned of roles and headers, up to 20. Both go to Luna as two brief lines, and as `retrieve` boost terms worth half a query term: they lift notes the line already matches, never retrieve one on their own.
- **Captions.** Bee reads the Teams or Zoom call window every 1.5 s while a captions or transcript region shows, backing off to 30 s while none does, and never faster than twice the last read took. What a window shows at first is history. A line is new once a newer line follows it or it reads the same twice; repeats (by normalised words), a line that grew (only the new words go) and a revised word in a recent line are dropped. Caption lines join the session as `Speaker: text` (or `Meeting: text`), follow the steering rules, and are never shared with a Teams sync. With the mic on, a caption that repeats one of the user's lines from the last 20 s is dropped. The mic stays the default input.
- **macOS permission.** agent-desktop needs Accessibility for Bee. Settings shows the state from `agent-desktop permissions`, and on "needs permission" says where to turn Bee on, with **Open Accessibility settings** (`x-apple.systempreferences:…Privacy_Accessibility`). Bee checks again every 10 s; it never prompts or opens the guide itself.
- **Fail-open.** A missing binary, spawn failure, `PERM_DENIED`, `PLATFORM_NOT_SUPPORTED`, a timeout or unreadable output logs one short warning per code and leaves the built-in detector alone. Failed reads back off to 60 s; an unavailable binary is retried after 5 minutes.
- **Privacy.** Snapshots, captions, names and titles stay in memory. Logs carry codes and counts only (`perf meeting-window caption lines +3`). The child gets Bee's environment without secret-looking variables, and `AGENT_DESKTOP_HOME` points at a private temporary folder (mode 0700) instead of `~/.agent-desktop`, because agent-desktop keeps snapshot ref maps there; Bee deletes it when the setting goes off and at quit.
- **Binary.** `main/agent-desktop.ts resolveAgentDesktop`: packaged, `Resources/agent-desktop/agent-desktop[.exe]` with `agent-desktop-macos-helper` beside it on macOS (`AGENT_DESKTOP_MACOS_HELPER_PATH`); in development, `node_modules/agent-desktop/bin/agent-desktop-<os>-<arch>`. `build.mac.extraResources` and `build.win.extraResources` copy only the target's own binary (and helper) per arch, plus `LICENSE` (Apache-2.0 text from `resources/licenses/agent-desktop-Apache-2.0.txt`). `build.files` keeps `node_modules/agent-desktop` out of `app.asar`.

## Teams audio fallback

Settings → Meeting context → **Hear Teams when not everyone has Bee** (`teamsAudioFallbackEnabled`, **off by default**). With the mic on in a Teams call where someone may not have Bee, Bee hears the Teams app's audio and transcribes it like the mic. It hears **the Teams app alone or nothing**: never the screen's or all system audio. Windows and macOS listen through an in-repo native helper (`native/teams-audio`); Linux does not.

Why off by default: it sends the words of people without Bee to speech-to-text, so it matches `readMeetingWindowEnabled`'s privacy default and waits for the user to switch it on. Bee used to mix all system audio into the mic whenever the mic was on. That was wrong, and it is removed. When on, the fallback keeps the old aim (hear the rest of the call) but only for Teams, only while someone may not be covered, and only through a Teams-only capture. Consent still needs a privacy (and, for wide use, legal) review.

```
renderer store: meeting tick (5 s) → window.bee.teamsAudio.status(token) → main/teams-audio-ipc.ts
  → main/teams-audio.ts createTeamsAudioStatus
      platform, TEAMS_APP_AUDIO, OS floor (os.release()) and helper installed → { supported, reason }
      setting off or unsupported → nothing else runs
      else teamsCall = built-in Windows Teams detector || meeting window reader's call is Teams || simulated Teams meeting
           coverage  = core/teams-audio teamsAudioCoverage(sync room members, the user, the Teams call window roster)
      permission = macOS Screen Recording as the last capture found it ("not-needed" elsewhere)
  → { platform, supported, reason, teamsCall, coverage, permission }   codes only; names stay in main
  main also renews the capture's lease, and stops a running capture its own check (teamsAudioAllowed) no longer allows
store teamsAudioNow → core/teams-audio teamsAudioPlan(setting, supported, teamsCall, mic on, coverage)
  "listen" → renderer/teams-audio.ts openTeamsAudio(token) → bee:teams-audio:start
     main: teamsAudioAllowed(fresh status, setting) or "refused"
        → main/teams-audio-capture.ts: spawn the helper (no args, stdio pipes, env without secrets), wait for status=ready
        → stdout s16le 16 kHz → createPcmFramer (100 ms frames) → core/speech startMicSession (segmenter → WAV → Grok STT)
        → bee:teams-audio:lines { id, lines } (text only) → store actions.teamsAudioLines → teamsAudioEcho dedupe
        → addLines as "Meeting: …" → pipeline; never teams.publish
  anything else (mic off, call over, covered, setting off) → bee:teams-audio:stop → stdin closed → helper exits 0
  helper exits by itself → bee:teams-audio:ended { id, failure } → store: failed until the plan leaves "listen"
```

- **When.** `teamsAudioPlan`: setting on, platform supported, a Teams call, mic on, and coverage not `covered`. Zoom and Google Meet never count. Main checks the same (`teamsAudioAllowed`, mic aside) before it starts the helper, and on every status poll while it runs.
- **Coverage** (`teamsAudioCoverage`). Not in a sync: `uncovered`. In a sync with no Teams roster from the meeting window reader (reader off, or no people region), or a roster at the reader's 20-name cap (it may be cut off): `unknown`. Otherwise `covered` when every roster name but the user's matches a sync member (`namesMatch`: every word of the shorter name matches its own word of the longer one, in any order, an initial matching a word it starts, at least one whole word; accents and punctuation ignored). Uncovered and unknown both listen. A user whose Teams name differs from their Bee display name reads as someone without Bee, so Bee listens.
- **Separate stream, in main.** Teams audio never goes into the mic's frames and never reaches the renderer. Main gives it its own segmenter and speech-to-text queue (`core/speech.ts startMicSession`, the mic's code), shows no "Got it…", and keeps its speech-to-text errors to a log code (the mic shows the same ones). A gap in the helper's audio (Teams silent) is filled with silence every 250 ms so a phrase in progress still ends. When the capture stops, queued phrases are dropped, not transcribed.
- **Dedupe** (`core/teams-audio.ts`, word Dice 0.6 via `echoesOwnLine`, 20 s). A Teams-audio phrase that repeats a recent own line, teammate line or caption is dropped. A teammate or caption line that arrives later and repeats a recent Teams-audio line replaces it in the session (it names the speaker) and starts no turn of its own. Teams-audio lines are never published to the sync.
- **Indicator.** While Bee hears Teams, the pill says "Listening to you and Teams audio…" when idle (`notch.ts`), and Live → Meeting says "Listening to Teams audio for people without Bee." Settings shows a status line (`teams-audio-message.ts`): not available (Linux, OS too old, helper missing), waiting, covered, listening, needs Screen Recording (macOS, with **Open Screen Recording settings**), Teams app not found, this OS cannot share Teams' sound, or could not hear Teams.
- **Fail-open.** A capture that will not start (helper missing, OS refused, permission off, Teams not running, no `ready` in 10 s) or whose helper exits by itself stops and is not retried until the plan leaves "listen" (call over, mic off). A `refused` start (main's status moved on) is not a failure; the next tick decides again. The mic, the sync and the pipeline never wait for it. Main's status never throws: a detector or sync failure reads as no call.
- **Lease.** The renderer's status poll (5 s) renews a 30 s lease. With no poll from a signed-in renderer for 30 s (window gone, signed out), main stops the helper and sends `ended` with no failure. At quit, main stops it too; a helper whose stdin closes (Bee died) exits on its own.
- **Privacy.** Audio stays in memory in main and is dropped once transcribed; only text crosses to the renderer (`teamsAudioLinesSchema`, 10 lines of 2000 characters at most per message). The helper gets Bee's environment without secret-looking variables. Logs carry codes and counts only (`teams-audio helper status=ready`, `teams-audio helper exit=5`, `teams-audio lines +1 total 3`, `teams-audio stt=err`); the helper's stderr is parsed for a status code and never logged. The helpers write no files.

## Processes and security

- The window is frameless, transparent, always on top and skipped from the taskbar. On first run it sits at the top centre of the primary display's work area. After that it keeps its position: each resize grows in place on the display the window is on, shifting only to stay inside that display's work area, and the last `{ x, y, displayId }` is saved in `settings.json` (main only) and restored at start-up. If that display is gone, it returns to the primary top centre. The maths is in `core/interface-scale.ts`. It resizes between 480 × 64 px (collapsed), 480 × 330 px (notch and Teams sync card), 480 × 360 px (notch and island response) and 480 × 640 px (expanded).
- The renderer runs with `sandbox: true`, `contextIsolation: true` and no Node integration.
- The renderer is served from `bee://renderer/` by `protocol.handle` (`main/renderer-protocol.ts`), not `file://`, so Clerk sees a stable origin. In development the handler proxies to the Vite dev server. Paths outside `out/renderer` return 404.
- The same handler sends the content security policy as a response header. Fonts are bundled (Instrument Sans woff2 in `renderer/src/fonts`), so `default-src 'self'` covers them and no font hosts are allowed. Remote scripts are allowed only from the Clerk Frontend API host (derived from the publishable key: `clerk.vedantb.com`) and `challenges.cloudflare.com` (bot protection). Images are allowed from `img.clerk.com`.
- Links opened from the renderer are denied; `https://` links (Clerk terms, help) open in the system browser.
- Only the `media` permission (microphone) is granted. `display-capture` is denied and `setDisplayMediaRequestHandler` always refuses, so no page in Bee can capture the screen or all system audio.
- Main may start one child for Teams audio (`native/teams-audio`, see [Teams audio fallback](#teams-audio-fallback)): the Teams app's sound only, stdio pipes, Bee's environment without secret-looking variables, stopped by closing its stdin.
- All IPC input is validated with zod in main. All IPC output is validated with zod in preload.
- Secrets are encrypted with `safeStorage` before they are written. If encryption is unavailable, they stay in memory for the session.

## Authentication

Bee uses `@clerk/electron` against the vedantb.com Clerk production instance (`shared/clerk.ts`; `VITE_CLERK_PUBLISHABLE_KEY` overrides the key at build time).

- **Main:** `createClerkBridge` runs before `app.whenReady()`. It registers the `bee` scheme as privileged, owns Clerk's token-cache IPC, and takes the single-instance lock on Windows and Linux. Bee stops booting when `isPrimaryInstance` is false. Bee then swaps the bridge's two OAuth IPC handlers for its own (see **OAuth**). Tokens persist via `@clerk/electron/storage` (`electron-store` + `safeStorage`; not persisted without OS encryption).
- **Preload:** `exposeClerkBridge()` alongside `window.bee`.
- **Renderer:** `ClerkProvider` from `@clerk/electron/react`. Signed out, the panel shows `<SignIn>`; signed in, it shows the Bee panel with a `<UserButton>`. The microphone button shows only when signed in.
- **Pipeline gate:** the renderer sends `getToken()` with each run. Main checks the token's issuer (`https://clerk.vedantb.com`), subject and expiry. The signature is not verified: this is a sign-in gate, not a security boundary, since the pipeline only uses the user's own key and notes.
- **OAuth:** social sign-in returns the system browser to `http://127.0.0.1:45789/sso-callback` (`CLERK_OAUTH_REDIRECT_URL`), not to `bee://renderer/`. A browser cannot show a custom-scheme URL as a page, so with `bee://` the tab stayed on the provider's last page.
  - `main/clerk-oauth-ipc.ts` runs right after `createClerkBridge`. It removes the bridge's `clerk:oauth-transport:get-redirect-url` and `clerk:oauth-transport:open` handlers and registers its own, which answer only the main frame of a `bee://renderer/` window. The token-cache handlers stay. A test checks the channel names against the package's built channel table, since the package does not export them.
  - `get-redirect-url` returns the loopback URL. `open` accepts only an https URL (zod). It starts the server in `main/clerk-oauth-loopback.ts` (no Electron imports) on `127.0.0.1:45789`, then opens the URL with `shell.openExternal`. When the browser reaches `/sso-callback`, it resolves `{ callbackUrl }` (the `@clerk/electron` transport contract) and shows and focuses Bee's window (`app.focus({ steal: true })` on macOS).
  - The server answers with one self-contained page from `main/clerk-oauth-page.ts`: Instrument Sans and the logo inlined, light and dark, a CSP that allows only its hashed script, and nothing echoed from the request. It reads `__clerk_status` and `__clerk_error_code` to show **Signed in to Bee**, **Almost done** (sign-in handed over to sign-up), **Sign-in was cancelled** or **Sign-in did not finish**. Cancels and errors still resolve with the URL, so clerk-js shows the error in the panel. The page links to `bee://renderer/` (**Return to Bee**; main brings the window forward on `open-url` and `second-instance`), and removes the query from the address bar.
  - Other paths and methods get 404. One sign-in runs at a time and times out after 3 minutes. The server stops after each sign-in, timeout, failure or cancel, so the next sign-in starts clean. The port is fixed because Clerk needs the exact URL allowlisted.
  - The bridge's own `bee://` `open-url` and `second-instance` listeners stay registered but never see a pending flow. electron-builder still registers the `bee` scheme (`build.protocols`, plus the Linux MIME type) for **Return to Bee** and team invites.
- **Dashboard:** Native API must be enabled. The allowlist for mobile SSO redirect must hold `http://127.0.0.1:45789/sso-callback` as well as `bee://renderer` and `bee://renderer/*`.

## AI calls

All model calls use the Vercel AI SDK (`ai`, `@ai-sdk/gateway`) against Vercel AI Gateway. Every call sends `providerOptions: { gateway: { serviceTier: "flex" } }`. No sampling parameters are sent (no temperature, topP, presencePenalty or frequencyPenalty).

### Why Jev does not use chat completions

The brief asked for Jev via the OpenAI-compatible `/v1/chat/completions` endpoint. On 26 September 2026 the Gateway rejected that call with `ModelTypeMismatchError`: "Model 'typesafe-ai/jev' is an evaluation model, not a language model. Use the evaluation generation API instead." The Gateway model list gives Jev `"type": "evaluation"`. Bee therefore calls Jev through the AI SDK evaluation API. To keep one client, Luna uses the same SDK.

### Jev prompt format

Defined in `src/core/jev.ts`.

- **State:** `{ transcript }`, the recent meeting lines joined by newlines, oldest first.
- **Questions:** one `score` question per candidate, keyed `c0`, `c1`, … in retrieval order. Each question's instructions carry the task, the note title and the note text:

  ```json
  {
    "type": "score",
    "instructions": {
      "task": "Rate how relevant this note is to what the meeting is discussing right now.",
      "noteTitle": "Acme renewal › Pricing",
      "noteText": "…"
    },
    "criteria": [
      "Irrelevant: unrelated to what is being discussed.",
      "Loosely related: same broad area, but not useful right now.",
      "Relevant: useful background for the current topic.",
      "Directly useful: answers or informs what is being discussed right now."
    ]
  }
  ```

- **Answer:** Jev returns a fractional score from 0 to 3 per question.
- **Ordering:** highest score first, with ties kept in retrieval order. Missing, wrong-type or out-of-range answers go last, in retrieval order.
- **Filter:** notes scoring below 1 (`JEV_MIN_SCORE`) are not sent to Luna. They still show in the panel.
- **Fail-open:** if the call throws, times out or returns no usable score, Bee keeps the retrieval order and reports `Jev ranking failed: <reason>` in the panel.

Question keys are positional (`c0`…) rather than note ids. Note ids contain characters such as `#` and `.`, and positional keys keep the mapping simple.

### Tools and sources
`src/core/tools.ts` holds the tool registry. `lunaTools()` returns the `ToolSet` passed to Luna. It always includes `web_search` (`anthropic.tools.webSearch_20250305({ maxUses: 3 })` from `@ai-sdk/anthropic`). It uses the basic version: the dynamic-filtering versions (20260209, 20260318) search from a code execution sandbox, and Haiku via the Gateway only ran `code_execution` there and never searched. Anthropic runs the search itself, so Luna calls that send it pin the Gateway to the Anthropic provider (`guideProviderOptions(tier, { web: true })` sends `only: ["anthropic"]`); bedrock or vertex may reject the tool. If the provider still rejects it, `guideWithLuna` retries once without `web_search`, with `order: ["anthropic"]` so the Gateway can fail over. Calls without web search (the meeting summary) also use `order`. The model decides when to search; Bee never forces it. Search runs in one provider-side step, and `sourcesFromGenerateResult` reads the links from `result.sources`, or else from the tool output (an array of `web_search_result` items). When `notesDir` is passed, the set also includes the four file tools below. New tools go into the same registry. `lunaTools({ notesDir, extraRoots, extra })` also takes `extra`, a `ToolSet` of MCP tools (see below). It stays synchronous; the caller loads MCP tools first. Built-in names win over an `extra` tool of the same name.

The file tools come from `src/core/fs-tools.ts` (`lunaTools({ notesDir, extraRoots })`); without `notesDir` they are omitted. They run in the main process (the pipeline does), so they use Node `fs`. They add to retrieval and Jev; they do not replace them.

| Tool | Does | Limits |
| --- | --- | --- |
| `list_dir` | Names, type and size in a folder; optional one level of subfolders | 200 entries; binaries marked `skip` |
| `search_files` | Case-insensitive match on file name or content; relative path plus a short line | 20 hits, 200-character snippet, 2000 files, depth 4 |
| `read_file` | Text of one file | 256 KiB file limit; 64 KiB returned, then truncated with a note |
| `append_note` | Creates or appends to a `.md` file | Notes folder only, file name only, 8 KiB per call, never overwrites |

Sandbox (`src/core/fs-sandbox.ts`): the roots are the notes folder (always first) plus `fsRoots` from `settings.json` (absolute paths, set in Settings, read on each pipeline run). Relative paths start at the notes folder. Backslashes count as separators on every platform. A path is refused if it holds a NUL byte, is empty, or resolves (`node:path`) outside every root. All symlinks are refused, and so is any path whose real location leaves its root. Listings and searches skip dotfiles and symlinks. A file is binary if its extension is on the binary list or its first 4 KiB hold a NUL byte. Tools return a short `Error: …` string instead of throwing.

`sourcesFromGenerateResult` reads `result.sources` and, if that is empty, `output.sources` in `result.toolResults`. It keeps unique `https` URLs, falls back to the hostname for a missing title, and returns at most 5. `PipelineResult.sources` carries them to the renderer, which shows each as a link chip after the tips' links (`core/link-suggest.ts` `sourceChips`, merged in `store.ts`; deduped by domain, not personalised). There is no separate Sources list. The list is empty when there is no key or Luna fails. A failed search fails open: Luna still returns tips, or the usual `Luna guidance failed:` error.

### MCP servers (Connectors)

The user connects MCP servers in the **Connectors** tab, between **Live** and **Settings** (`renderer/src/Connectors.tsx`), so Luna can use their tools, for example vmem, Eva or a local command. Each connector is one row: icon (site favicon), name, **Connect** or **Disconnect**. **vmem** is a preset (`https://<deployment>.eu-west-1.convex.site/mcp`, vmem's Convex prod MCP endpoint): Connect saves it enabled and signs in with MCP OAuth (see below); the row shows Disconnect only once tokens are stored (`hasAuth`), and Disconnect removes the server with its tokens. **Eva** is a second preset (`https://<deployment>.eu-west-1.convex.site/mcp`, favicon `eva.vedantb.com`; `isEvaConnector` in `shared/mcp-names.ts` matches the name `eva` or those hosts) and behaves the same. A custom HTTP row with auth "none" also runs Connect through `connectMcpServer` and counts as connected when enabled with tokens. **Add custom**, or a click on a custom row, opens the full form (transport, URL, auth, stdio, tool switches). Two transports, both through the official `@modelcontextprotocol/sdk` (a runtime `dependency`, so it lands in `app.asar`):

- **Streamable HTTP** (`StreamableHTTPClientTransport`): `https`, or `http` on localhost only. Auth is none, a bearer token (`Authorization: Bearer …`) or a custom header (name plus value).
- **stdio** (`StdioClientTransport`): command, args (one per line, or space-separated) and env `KEY=value`.

Custom connectors can still paste a bearer token or header. Remote servers with auth "none" (including the vmem preset) sign in with MCP OAuth, described below.

`src/core/mcp.ts` (no Electron imports) connects, lists tools and calls them. `loadMcpTools(configs)` connects to every server at once and wraps each enabled tool as an AI SDK `tool()` named `{prefix}__{tool}`. The prefix is the server name cleaned to `[a-zA-Z0-9_-]` (24 characters at most, no `__`) and lowercased, so the "Eva" preset's tools are `eva__…`; names are capped at 64 characters and made unique. It also returns `servers` (`{ name, prefix, toolCount }` for each server that listed, counting only tools left switched on) and `errors`. A server listing more than 100 tools (`MCP_MAX_TOOLS`) keeps the first 100, and main warns with the server name and how many were dropped. Connect and list time out after 10 s, each call after 15 s. A server that fails or hangs is skipped (main logs its name and a short reason, never secrets), so the others still load. A tool call that fails returns a short `Error: …` string; it never throws into `generateText`. Error text has every secret value masked.

`runPipeline` calls `loadMcpTools` (passed in by `registerMeetingIpc`, which reads enabled servers and decrypted secrets from settings on each run, like `fsRoots`) only when Luna is about to run, hands the tools, `servers` and `errors` to `guideWithLuna({ extraTools, connectedServers, unavailableServers })`, and closes every connection (and stdio child process) when the run ends. `settings.mcpConfigs()` leaves out enabled sign-in servers (HTTP, auth "none") with no stored tokens; `settings.mcpSignedOut()` names them and `registerMeetingIpc` adds them to `errors` as "not signed in". When any server is connected or unavailable, `lunaMcpSystem` adds an MCP block to the system prompt that names them, for example "Bee connectors connected now: vmem (77 tools, named vmem__<tool>), Eva (84 tools, named eva__<tool>)." and "Not available this turn: X (reason)." Luna answers "what is connected" from that list, and is told that a server's own tools such as `connectors_list` describe that service's data sources, not Bee's connectors. Tool-name examples use the real prefixes. It still says to call the tools before guessing about the user's data, and never to invent a result. A schema error drops the tools it names and retries; a tool-count error ("array too long") drops every MCP tool at once. After a drop, each server's count is recomputed and a server left with no tools is listed as unavailable ("tools skipped after a schema error"). `PipelineResult.mcpErrors` (at most 20, short reasons, never secrets) reaches the Live tab as one muted line (`mcpErrorNote` in `renderer/src/island.ts`), for example "Eva unavailable: sign in again from Connectors".

MCP sign-in (OAuth): vmem and other remote servers with auth "none" use standard MCP authorization through the SDK. `core/mcp-oauth.ts` (no Electron imports) wraps the MCP client helpers in `@vvedantb/server` (a runtime `dependency`, so it lands in `app.asar`) with Bee's options; it keeps the stored state schema local. The provider implements `OAuthClientProvider` over injected storage and an injected `redirectToAuthorization`: client name "Bee", `token_endpoint_auth_method: "none"`, authorization code with PKCE, dynamic client registration, refresh tokens. `authorizeMcpServer` connects first; on 401 the SDK reads the protected resource metadata (RFC 9728, from `WWW-Authenticate` or `/.well-known/oauth-protected-resource`), then the authorization server metadata, registers a client and opens the system browser (`shell.openExternal`, http(s) only). The redirect is a one-shot HTTP server on `127.0.0.1` with a random port (`main/mcp-oauth-loopback.ts`, the package loopback with Bee's page texts, path `/callback`, `state` checked, five-minute limit). It is not `bee://`, which Teams invites use, and not the fixed port 45789 that Clerk sign-in uses (`main/clerk-oauth-loopback.ts`). That exact URL is registered in `redirect_uris`, so a saved client is registered again when the port differs. Tokens and client information are stored encrypted in `mcpSecrets` and refreshed automatically (the SDK refreshes on a 401 and the provider saves the result). `bee:mcp:authorize` runs the flow for a server id, then lists tools, saves them and switches the server on. Every HTTP provider, interactive or not, has `saveClientInformation`, so the SDK never fails with "OAuth client information must be saveable" on a 401 that advertises dynamic registration. Luna and link chips get a provider that still never opens a browser (`createMcpOAuthProvider` without `redirectUrl`: `redirectToAuthorization` rejects with "Sign in from the Connectors tab"), so a missing or expired sign-in fails open. Tokens never leave main.

Personalised links use the same client. `isVmemConnector` (`shared/mcp-names.ts`) matches an enabled server whose name slugs to `vmem` or whose URL host is `vmem.vedantb.com` or `vmem.projectv.uk` (the preset row uses the latter for its favicon); `settings.vmemConfig()` returns it with its secrets, and `settings.linkSettings()` returns `{ enabled, hasVmem }`. The `personalisedLinks` setting defaults to whether such a server is enabled. `core/vmem-history.ts` (`createVmemSearch`) keeps one warm `connectMcp` connection: opened at app start when the connector is enabled and signed in, and on each save, remove, enable or sign-in (`refresh()`), closed on Disconnect and at quit. A search picks `memory_search` (else `search`, else a tool with "memory" and "search" in its name) and calls it once per source (`browsing-history` and `bookmark`, or the matching values of an enum) with a 1 s limit each, then merges the results, so a chip pays for the call and not for connecting. A cold connect (5 s limit) runs in the background and a chip that has to wait is cut off by the 2 s enrich budget (`ENRICH_TIMEOUT_MS`). A failure other than a timeout drops the connection so the next search reconnects. `parseHistoryHits` reads the text or JSON output without a schema: it tolerates missing fields, and returns `[]` for anything unreadable. Without a connector, or on failure, history is `[]` and Jev still scores the plain domain chip. `createLinkEnricher` takes an `onFallback(reason)` callback; `link-ipc.ts` logs it with `console.debug("Bee: personalised links fell back:", reason)`, and unexpected MCP errors with `console.warn`.

Storage (`main/settings.ts`, `settings.json`):

- `interfaceScale`: the Interface size in Settings, one of 0.9, 1 (default), 1.1, 1.25, 1.5, 1.75. Anything else on disk reads as 1, and a save accepts only those values. Main applies it with `webContents.setZoomFactor` on every window and scales the overlay bounds by the same factor (`core/interface-scale.ts`), keeping the current window mode. It takes effect on save, like meeting mode.
- `mcpServers`: `{ id, name, enabled, transport, url?, command?, args?, envKeys?, auth: { type, headerName? }, tools?: { name, description, enabled }[] }`. At most 20 servers and 100 tools each, validated with zod. Names must be unique after slugging. An invalid list is dropped without losing the other settings.
- `mcpSecrets`: one `safeStorage` ciphertext (base64) of JSON keyed by server id, holding the bearer token or header value, the stdio env values and, for OAuth servers, an `oauth` blob (tokens and client information, each stamped with its authorization server by the SDK). Secrets are never written into `mcpServers`. If encryption is unavailable they stay in memory for the session, like the gateway key.
- `view` objects carry `hasAuth` and env key names only. On save, a secret that is omitted stays as it was and `""` clears it. Changing the auth style drops the old secret.

IPC (`main/mcp-ipc.ts`, zod in main, parsed again in preload): `bee:mcp:list`, `bee:mcp:save`, `bee:mcp:remove`, `bee:mcp:set-enabled` (a server, or one tool), `bee:mcp:authorize` (sign in; see below) and `bee:mcp:test`. Test connects, lists, saves the list (a known tool keeps its switch, a new tool starts on) and returns `{ ok, tools?, error? }`. The Settings list shows each server's tools with a per-tool toggle.

### Luna prompt format

Defined in `src/core/luna.ts`. The system prompt asks for a few short tips (the cap is in the message tail), one per line, under 20 words each. If the latest lines ask a direct question, the first tip answers it: from the notes when they cover it (cited as `[n1]`), otherwise from general knowledge, with a brief caveat when the answer may have changed since training. Otherwise tips suggest what to say next, citing notes. Tips must not invent facts about the user's own work. If there is nothing useful, the model replies `NONE`. If the notes do not cover a question and the fact is public or may have changed (office holders, news, scores, prices), Luna calls `web_search` and may end the tip with the site domain; a `[web]` tag the model still adds is stripped (`parseLunaTips`). A follow-up ("why…") gets its own answer: on a new turn the latest settled tips go to Luna as context (`earlier`, after the transcript), not on screen. It does not search for stable facts or sums. If the notes do not cover a question about the user's own notes or files, Luna uses `list_dir`, `search_files` and `read_file` (injected `[n1]` notes first, never `web_search` for private facts), and calls `append_note` only when the user clearly asks to add or save a note. The user prompt holds the last 8 transcript lines and the notes labelled `[n1]`… The panel shows the same labels next to each note.

Prompt caching: `buildLunaPrompt` returns the parts in cache order, and `lunaRequest` sends them with explicit Anthropic cache breakpoints (`ANTHROPIC_CACHE` in `core/gateway.ts`; not the Gateway's `caching: "auto"`). The system (`LUNA_SYSTEM`, the MCP block, the meeting rules) is the same on fresh and steering turns and carries the first breakpoint. The user message has three text parts: the context (meeting brief and notes, second breakpoint), the transcript window (no breakpoint: it slides every phrase), and the tail (shown tips, the tip cap of 2 or 3, `LUNA_STEERING_RULES` while tips are kept, and the `Tips:` cue). A prefix under Anthropic's minimum cacheable length is not cached. `guideWithLuna`'s `onFinish` and the `perf luna` line report cache read and write tokens. The summary call puts the breakpoint on its system message.

### Summary prompt format

Defined in `src/core/summary.ts`. The system prompt asks for exactly three `##` sections (Decisions, Action items, Topics) of short bullets, action items as `- Owner: task` when an owner is named, `- None recorded.` for an empty section, and no facts beyond the transcript and notes. The user prompt holds the session transcript and the titles of the notes cited. `parseSummaryMarkdown` drops code fences, titles and preamble, and rejects a reply missing any section.

## Renderer state

One small external store (`renderer/src/store.ts`, read with `useSyncExternalStore`) holds settings, the active tab, the meeting session (not rendered), the last result, the summary state, the microphone state, the update state and the Teams view from main. A `setInterval` outside React drives the 2 s sync tick. Forms are uncontrolled and read with `FormData` on submit. There is no `useEffect`. The React Compiler is enabled.

Saved secrets show as a disabled field reading `•••••••• (saved)` with **Replace**. The form remounts after a successful save, so typed secrets clear and saved fields go back to masked.

## UI

- Font: Instrument Sans (variable, 400–700), self-hosted woff2 with the SIL OFL licence alongside.
- Icons: `@tabler/icons-react` (bundled into the renderer; unused icons are tree-shaken).
- Island: the notch is a pill. While a run is busy it shows the tool Luna is using (`bee:luna:activity`, `{ runId, tool, phase: "start" | "end" }`, sent from main by `guideWithLuna` from the stream's tool parts, so provider-run `web_search` shows as it starts, plus `onToolExecutionStart`/`End` and an `onStepFinish` fallback, deduped per call; the store keeps the run's calls in flight in `tools`; `activityLabel` maps `web_search` to "Searching the web", the file tools to "Reading notes", `append_note` to "Writing a note", an MCP tool named `prefix__tool` to "Using prefix…", anything else to "Thinking…"). When the answer arrives, the same surface grows downward with the tips (17 px) and link chips, search sources included. The body closes with the × button, or folds back to the pill's one line after `islandOpenMs` (30 s plus 1 s per 3.3 words shown) with no new result, scroll, busy run or pointer on the island. Opening the full panel cancels the timer. A new result reopens the body. Clicking the one-line answer in the pill opens it in full in the island (`fullText`, window size `response`), never the panel. Like any answer, it opens at the top: the body never scrolls by itself, so the user reads from the first line. It stays until the × button, a click outside the island or a new turn. Only the chevron opens the panel. A line starts a new turn (the last answer goes, nothing is kept) unless it interrupts a busy run (`core/steering.ts` `isNewTurn`). A run answering a question is not cancelled by later lines that are not questions; they wait for it (`waitsForRun`). The body does not show while the panel or the Teams sync card is open. Tips are not streamed: `generateText` returns them whole, so the finished tips fade and slide in.
- Logo: `renderer/src/BeeLogo.tsx` is an inline SVG honey orb with two stripes, glassy wings, antennae and pill eyes. It sits at the start of the notch (20 px, in place of the old dot) and above sign-in. `logo.ts` picks detail by size: below 24 px it drops the glow, antennae and catchlights and crops the view. `tone` is the background: `"dark"` (default, the app's surfaces) draws white glassy wings; `"light"` draws them grey (#d4d4d8 to #cfcfd4) with a #8a8a92 outline so they read on white. It blinks every 3–5 s (phase per instance). In the notch, `notch.ts` `logoState` picks one of seven states (error > searching/tool > thinking > done > listening > idle), each with its own motion and extras (mic-level ring, orbiting dots, figure-8 with magnifier, honeycomb, a one-shot loop and sparkle for `LOGO_DONE_MS`, drooped grey wings with a red dot); path keyframes are generated in `logo.ts`. The animated 20 px view widens to `5 5 54 54` so extras fit. With motion off each state holds a still pose. `animated={false}` renders the plain static mark. `resources/bee-logo.svg` and `bee-logo-light.svg` are the two tones at 512 px, kept in step by file snapshots in `logo.test.ts` (`npx vitest run -u` rewrites them).
- Icons: `npm run icons` (`scripts/make-icons.mjs`) bundles `BeeLogo` with esbuild, renders it with `@resvg/resvg-js` and writes every icon; commit the output. The app icon is the dark-tone mark on a warm dark tile (#2b241a to #110f0b, Bee's surface colour, so the orb glows as in the notch), drawn again at each size so small sizes get the simple mark. macOS (`icon.icns`, master `icon-mac.png`) follows the Big Sur grid: an 824 px superellipse tile with a drop shadow in a 1024 px canvas. Windows (`icon.ico`, 16–256 px) and Linux (`icon.png`, 512 px) use the tile with a 3 % margin and no shadow. The macOS tray loads `trayTemplate.png` (16 px, hand-placed pixels) and its `@2x` sibling (32 px): a black-and-alpha side-on bee (teardrop body with stinger and two stripes, round head, two fanned wings, no face) that the menu bar tints. Windows and Linux load the colour `tray.png` (32 px, light tone, as taskbars may be light or dark). The site gets `docs/icon.png`, `docs/favicon.ico` and the light-tone mark as `#i-mark` in `docs/index.html`. They stay out of `app.asar` (`build.files`) except the tray PNGs, which main reads at run time. `scripts/make-icons.test.mjs` checks that the build config points at icons that exist and that the tray sizes are right.
- Motion: CSS only, 150–220 ms, transform and opacity. Panel slides in on expand and fades out before the window shrinks (`COLLAPSE_MS` 160 in the store matches the CSS). Tabs, notch status, tips and notes fade or rise in. `prefers-reduced-motion` turns motion off.

## CI

`.github/workflows/ci.yml` runs on every push and pull request. A `windows` job builds the Teams audio helper (`npm run build:teams-audio:win`: fails if it does not compile or answer `--version`), runs `npm run typecheck` and `npm test`, packages an unpacked app (`electron-builder --win dir`) and checks `resources/teams-audio/teams-audio-helper.exe` is in it and answers `--version`. A `macos` job builds both Teams audio helpers (arm64 and x64, checked with `lipo`), runs `npm test`, `npm run build`, the replay E2E and an unsigned `electron-builder --mac dmg zip --arm64 --x64`, checks each `Bee.app` carries its own arch's helper and that the arm64 one answers `--version`, then uploads the artifacts. No job joins a Teams call. `release-windows.yml` ("Release") builds Windows and macOS in parallel, with the same helper builds and packaged-helper checks; a final `publish` job downloads both and makes the one GitHub release.
